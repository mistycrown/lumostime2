# 待办本地提醒

2026-10-18：Android 提醒弹窗新增默认关闭的“同步系统日历”开关，安排/截止分别设置。显式开启后申请读写日历权限，写入独立的本机 `LumosTime 待办提醒` 日历；事件在选定提醒时刻开始，持续一分钟，并设置到时提醒。不写云日历，不增加持续响铃的系统闹钟。

日历项由日历应用提醒，不要求 LumosTime 或 WebView 常驻。请允许手机日历应用通知，并在日历应用中显示该日历。普通退出 LumosTime 后本地通知仍可触发；系统强行停止 LumosTime 后可由日历应用独立承担提醒，但日历自身关闭、受限、通知被禁或手机关机时仍无法保证送达。两条通道均开启时可能收到两条通知。依据：[Android Calendar Provider](https://developer.android.com/identity/providers/calendar-provider)、[AlarmManager](https://developer.android.com/develop/background-work/services/alarms)。

同一提醒使用稳定标识，重复保存/恢复不会重复创建事件或重建已就绪的提醒。修改未来提醒的名称/日期会更新同一事件；关闭日历同步保留本地提醒，完成/删除待办、清除日期或选择“不提醒”会删除对应的本应用日历项。已经过去的事件不新建、不重新设置提醒。日历同步批处理失败不影响本地通知；弹窗显示独立错误，恢复权限并回到应用后重试。撤销日历权限期间无法修改或删除已有日历项，恢复授权后再清理。

2026-10-18：待办快捷操作栏的“安排到 / 截止到”卡片右上角也提供铃铛入口，对应日期存在时显示。未设置提醒为灰色，已设置提醒仅改变铃铛图标颜色，保持透明背景且不超出卡片标题栏；点击后复用同一提醒弹窗和四位数字时间输入。两处提醒独立保存或关闭，操作后保留快捷栏；清除对应日期会隐藏入口。待办列表与时间线入口均已接入，深色模式适配已选颜色。

2026-10-18：提醒时刻改用添加记录同款的小时/分钟数字输入。点击字段全选已有内容，输入两位小时后自动跳到分钟，连续输入 `0845` 即为 `08:45`；使用数字键盘，不弹出系统时间选择器。Chromium 实际键入检查已验证自动跳转、已有数值替换、前导零、时分范围限制和保存后重新打开。

待办设置安排日期或截止日期后，对应日期旁出现“提醒”。两个日期可分别设置提醒日期与时刻，也可分别关闭。空名称待办先填写名称；已完成待办不显示提醒入口。

弹窗支持当天、提前一天、提前三天和自选日期。提醒保存为相对来源日期的天数与本地时刻，例如“截止前一天 18:30”。来源日期改期后保持这个规则。清除来源日期或开启互斥的循环规则会清除相应提醒，复制待办不继承提醒。完成或删除待办会从本机调度快照中移除。

## 平台行为

- Android 使用独立 `TodoReminder` 插件；不依赖助手开关、AI、网络或 WebView 常驻。
- 成功保存待办后，按落盘顺序提交原生快照。原生保存投递状态，用一个 AlarmManager 任务批量处理到期提醒，再注册下一个任务。
- 重启、应用更新、时间/时区变化、准时提醒权限恢复和应用回到前台时重建调度。时刻按手机当前时区解释；不存在的夏令时时刻不调度。
- 通知权限或提醒渠道关闭时，提供设置入口；也可以授权并开启系统日历后独立保存日历提醒。缺少准时提醒权限时本地通知使用非精确调度，显示“提醒可能延迟”。
- 已投递提醒不因重新打开应用或重建调度重复通知。最近 24 小时内未投递的提醒在恢复时可补发；更早的过期提醒不补发。
- 点击 Android 通知后打开当前保存的对应待办；待办已删除则提示。
- Web/Electron 使用应用运行期间的浏览器通知，弹窗明确显示“应用运行时提醒”。此版本不提供桌面应用完全退出后的定时通知。
- 用户强行停止应用、关机、撤销权限及厂商特殊省电策略仍可能影响提醒，不能承诺这些情况下必达。

`TodoItem.reminders` 是配置，可随原有待办备份/同步，其中 `calendarSync: true` 表示对应日期提醒选择了系统日历。Android 调度快照、投递标记和日历错误/清理状态保存在本机 SharedPreferences，供无 WebView 的 Receiver 使用；系统日历只维护专用日历中带本应用标记的事件，不修改用户自行创建的事件。没有接入系统闹钟或飞书。

## 验证

```powershell
node node_modules/vitest/vitest.mjs run src/utils/todoReminderUtils.test.ts src/services/todoReminderService.test.ts src/components/TodoDetailModal.test.tsx src/hooks/useTodoManager.test.ts
node node_modules/vitest/vitest.mjs run src/components/TodoQuickActionsModal.test.tsx src/hooks/useTodoQuickActions.test.ts src/components/TodoDetailModal.test.tsx
node scripts/check-todo-reminder-time.mjs
node scripts/check-todo-reminder-types.mjs
npm run build
node scripts/test-todo-reminders.mjs
npx cap sync android
```

Java 检查只编译无 Android 依赖的独立时间策略及测试到临时目录，不编译 Android 应用。交互检查使用隐藏、隔离的 Electron 和实际 DataProvider、待办详情、日期/提醒弹窗，模拟系统权限，不发送真实通知；截图显式加载 Windows 微软雅黑字体。

`check-todo-reminder-time.mjs` 同时验证日历协调策略：重复同步、双日期隔离、关闭/完成/删除清理、改名保留提醒、改期/时区更新、缺失提醒修复、过期不补建和重复事件清理。此检查不执行 Android Calendar Provider 或权限弹窗。

原生桥接需要由用户重新打包 APK，单独更新 Web 资源不能给旧安装包增加插件。安装后验收：

1. 安排与截止分别设为未来时间；允许通知和准时提醒，退出页面并锁屏，核对通知。
2. 普通进程回收后、断网时核对提醒；分别测试厂商一键清理与系统强行停止，记录差异。
3. 重启手机，在不打开应用的情况下核对未来提醒。
4. 修改日期、关闭提醒、清除日期、完成/删除待办，确认旧提醒不再触发。
5. 同时到期的多个待办均提醒；通知打开对应待办，重新打开应用不重复通知。
6. 撤销/恢复通知与准时提醒权限，检查状态和调度恢复；修改系统时间与时区后核对新时刻。
7. 默认无日历授权请求；开启系统日历并授权后，在日历应用检查独立日历、名称、时间和到时提醒。分别测试普通退出、进程回收及强行停止 LumosTime 后由日历提醒。
8. 重复保存/重开不新增重复日历项；改名改期更新原事件；关闭同步保留本地通知，完成/删除/清除日期/不提醒清理对应事件；用户自行创建的日历事件保持不变。
9. 拒绝和撤销日历权限，核对错误和本地通知；恢复权限重开应用后重试清理。禁用应用通知但开启日历权限，核对日历提醒可独立保存。禁用日历应用通知时核对设备行为。

以上实机项目不能由网页冒烟或独立 Java 检查替代。
