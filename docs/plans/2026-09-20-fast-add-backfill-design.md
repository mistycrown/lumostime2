# 快速添加补记设计

## 目标

增加一条以 `快速添加补记：` 为协议前缀的快速补记链路。用户从 AI 首页或对话输入框加号菜单进入时，只需补充补记描述；发送后 AI 请求只携带描述和精简 `create_log` 工具约束，避免普通人设、历史上下文和其他工具拖慢返回。

## 交互

- AI 首页增加 `+补记` 快捷指令。点击后进入当前 AI 对话，不自动发送，并将输入框预填 `快速添加补记：`。
- 对话输入框左侧加号菜单增加 `快速添加补记`，点击后关闭菜单并预填同一前缀，光标定位到末尾。
- 只有发送文本以 `快速添加补记：` 开头时进入快速链路；前缀之后的文本作为补记描述。
- 请求成功后在当前会话保留用户消息和统一助手回复 `已添加补记`，同时展示现有补记应用卡片及撤销能力。

## 架构与数据流

1. `AIBackfillChatModal` 在普通 `handleSend` 之前识别快捷前缀。
2. 新增 AI service 精简 structured JSON 方法，system prompt 只声明 `create_log` 输出契约，user prompt 只放补记描述；不传人设、会话历史、长期记忆、提醒、日志查询或其他工具。
3. 快速工具允许 AI 返回日期、时间、描述以及分类/活动名称；应用端使用当前分类字典做本地匹配。未匹配到分类或活动时回退到 `uncategorized / quick_punch`，保证快捷输入可落地。
4. 生成标准 `AIBackfillToolCall` 后复用现有 `assistantActionExecutor.applyLogToolCalls`、消息应用动作渲染和撤销能力。
5. 快捷请求完成后复用现有消息 pending/result 替换和应用动作渲染逻辑；无有效工具调用或执行失败时按失败处理，不写入补记。

## 错误处理与兼容性

- AI 配置缺失、网络失败、JSON 无效或未返回有效 `create_log` 时，沿用现有错误消息和重试能力。
- 快速链路不触发普通助手的记忆、提醒、查询和其他工具副作用。
- 不改变普通聊天、已有快捷指令和待办页现有入口行为。

## 验证

- 为快速前缀识别、工具调用归一化、分类/活动匹配与默认回退补充聚焦测试。
- 运行相关 Vitest 和 `npm run build`，并检查 AI 首页与对话加号菜单的预填及光标位置。
