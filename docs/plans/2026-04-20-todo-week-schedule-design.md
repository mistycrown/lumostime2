# 待办周视图排期（第一版）设计
日期：2026-04-20

## 目标
在现有待办系统上增加第一版排期能力，但范围严格控制为：

- 在待办详情页为每条待办增加 `分配日期`、`截止日期`、`循环规则`
- 在待办页增加 `列表 / 周视图` 切换
- 周视图按一周拆成 7 行，每一行代表一天，显示当天命中的待办

本次不做月视图、不做拖拽排期、不做循环实例表、不做改单次循环行为。

## 设计原则

- 继续沿用同一套 `TodoItem` 数据结构，不额外引入独立“日程对象”
- `分配日期`、`截止日期`、`循环规则` 是三个并行维度，不互相替代
- 循环规则只负责提醒显示，不因为完成一次而自动消失
- 周视图是派生视图，不额外持久化任何 occurrence 数据
- 视觉风格采用极简印刷风，靠留白、字重、细线和小图标区分语义

## 方案对比

### 方案 A：单独新增日程对象

优点：

- 日程语义独立
- 后续扩展复杂日历交互会更自由

缺点：

- 和现有 todo、详情页、同步、统计体系割裂
- 第一版成本和迁移成本都偏高

### 方案 B：在 `TodoItem` 上扩展日期字段并做周视图派生

优点：

- 和现有待办系统天然相通
- 改动范围可控
- 适合本次“先做第一版周视图”的目标

缺点：

- 后续如果做非常复杂的日历实例行为，仍需继续演化

### 结论

采用方案 B。

## 数据模型

在 `src/types.ts` 的 `TodoItem` 上新增可选字段：

```ts
scheduledDate?: string; // 分配日期，YYYY-MM-DD
deadlineDate?: string;  // 截止日期，YYYY-MM-DD
recurrenceRule?: {
  frequency: 'daily' | 'weekly' | 'monthly';
  startDate: string;      // YYYY-MM-DD
  endDate?: string;       // YYYY-MM-DD
  interval?: number;      // 默认为 1
  weekdays?: number[];    // weekly: 0-6
  monthDays?: number[];   // monthly: 1-31
};
```

说明：

- 没有 `scheduledDate` 的待办仍然是普通待办
- `deadlineDate` 独立存在，可与 `scheduledDate` 或 `recurrenceRule` 同时存在
- `recurrenceRule` 是规则，不生成单次实例

## 规则定义

### 分配日期

- 表示“计划在哪一天做”
- 当 `scheduledDate` 命中某一天时，该待办出现在该天的周视图中

### 截止日期

- 表示“最晚应在哪一天前处理”
- 当 `deadlineDate` 命中某一天时，该待办也出现在该天的周视图中

### 循环规则

- 表示“哪些日子持续提醒我”
- 不支持改单次
- 不支持跳过本次
- 不支持完成后自动隐藏未来提醒

### 多规则命中

同一条待办如果在同一天同时命中多个条件：

- 周视图中只显示一张卡片
- 卡片上并列展示多个小图标
- 不复制为多条记录

## 详情页设计

修改 `src/components/TodoDetailModal.tsx`，在细节页增加一个新的“时间安排”区块，包含：

- 分配日期选择器
- 截止日期选择器
- 循环规则设置器

第一版循环规则只支持：

- 每天
- 每周几
- 每月几号

第一版不支持：

- 排除日期
- 跳过本次
- 仅改单次
- 复杂 RRULE 文本编辑

## 周视图设计

修改 `src/views/TodoView.tsx`，增加 `list / week` 双模式。

### 布局

- 页面主体按一周拆成 7 行
- 每一行代表一天
- 从上到下排列一周日期
- 行头显示星期和日期
- 行内容区纵向堆叠当天命中的待办卡片
- 页面整体纵向滚动

### 显示内容

每一天展示三类命中的待办：

- 分配到这一天的待办
- 截止日在这一天的待办
- 循环规则命中这一天的待办

### 排序建议

同一天内的卡片按以下顺序显示：

1. 同时有分配日期和截止日期的待办
2. 仅有分配日期的待办
3. 仅有截止日期的待办
4. 仅有循环提醒的待办
5. 其他命中组合按标题稳定排序

## 视觉设计

整体采用极简印刷风：

- 主色以纸白、石灰、黑灰为主
- 降低大面积彩色块使用
- 通过留白、细边框、字重、节奏来建立层级

三类日期语义通过不同小 icon 区分：

- 分配日期：日历类 icon
- 截止日期：旗标或时钟类 icon
- 循环规则：循环箭头类 icon

卡片表现建议：

- 分配日期：普通浅底细边框卡片
- 截止日期：更强字重，或带一条更明显的左侧细线
- 循环规则：更轻的灰底或虚线边框

如果同一张卡片有多个日期语义：

- 保留单一卡片
- 图标并列显示在标题前或标题右侧
- 不让图标喧宾夺主

## 悬浮切换按钮

待办页的列表 / 周视图切换按钮，交互和样式对齐记录页现有悬浮切换按钮。

复用：

- `src/components/FloatingButton.tsx`
- 全局 `.floating-button` 主题变量样式

要求：

- 有使用主题和未使用主题两种样式
- 支持默认 Lucide icon
- 支持 `uiIcon`
- 图标策略沿用现有 `UIIcon + fallbackIcon` 机制

按钮语义：

- 在列表模式下，按钮表示“切换到周视图”
- 在周视图模式下，按钮表示“切换回列表”

## 派生计算

周视图不新增持久化数据，只从 `todos` 派生。

建议抽出独立工具函数，至少包含：

- 生成当前周 7 天日期
- 判断某个 todo 是否命中指定日期
- 合并同一天的多重命中语义
- 输出周视图可直接渲染的数据结构

建议的数据形态：

```ts
interface TodoDateBadges {
  scheduled: boolean;
  deadline: boolean;
  recurring: boolean;
}

interface WeekTodoEntry {
  todo: TodoItem;
  badges: TodoDateBadges;
}

interface WeekDayBucket {
  date: string; // YYYY-MM-DD
  items: WeekTodoEntry[];
}
```

## 兼容性与同步

- 新字段全部为可选字段，老数据无需迁移脚本即可兼容
- 导出、导入、同步时自动跟随 `todos` 一起传输
- 没有设置任何日期字段的待办，行为与当前版本保持一致

## 测试重点

- 老待办数据没有新字段时，列表页和详情页不报错
- 设置分配日期后，待办能正确出现在对应周视图日期
- 设置截止日期后，待办能正确出现在对应周视图日期
- 设置每天 / 每周 / 每月循环后，规则命中正确
- 同一待办同一天命中多个语义时，只显示一张卡片且徽标正确
- 列表模式和周视图模式切换正常
- 悬浮按钮在主题样式和非主题样式下都显示正确
- `uiIcon` 和 Lucide fallback 都能正常工作
