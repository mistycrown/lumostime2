# 自我认知 Tab 设计

## 背景

原则库当前保存的是用户用于行动和判断的原则。新的“自我认知”能力用于保存用户对自身能力、身份和行动风格的定义，并为每条定义维护具体描述。

这类内容不适合塞进现有原则卡片字段。原则回答“我该怎么做”，自我认知回答“我是谁，我已经证明过什么”。第一阶段先实现手动维护，不接入 AI 自动生成。

## 第一阶段目标

在原则库页面中新增“自我认知” Tab，让用户可以：

- 手动创建一个自我认知条目。
- 在自我认知编辑弹窗内逐条添加描述。
- 编辑和删除已有描述。
- 编辑和删除自我认知标题。

暂不实现 AI 查询、AI 自动添加、自我认知详情页、描述来源联动日志或复盘。

## 页面结构

原则库页面顶部保留返回按钮和标题。在标题区域下方增加分段切换：

- 原则
- 自我认知

切到“原则”时保持当前原则库列表和添加流程。切到“自我认知”时，主内容区展示自我认知列表。

“添加新原则”按钮只在原则 Tab 展示。“自我认知” Tab 使用自己的“添加自我认知”按钮。列表页只负责展示自我认知摘要，不在列表卡片内直接添加描述。

## 数据结构

新增本地存储 key：

```ts
const SELF_BELIEFS_STORAGE_KEY = 'lumostime_self_beliefs';
```

数据结构：

```ts
interface SelfBelief {
  id: string;
  title: string;
  descriptions: SelfBeliefDescription[];
  createdAt: string;
  updatedAt: string;
}

interface SelfBeliefDescription {
  id: string;
  text: string;
  date?: string;
  source: 'manual' | 'ai';
  createdAt: string;
  updatedAt: string;
}
```

第一阶段不添加额外长正文。标题本身承担“我是一个什么样的人”的表达，例如“我是一个学习能力很强的人”；`descriptions` 用来保存支撑这句话的具体经历和说明。

## 自我认知条目交互

### 添加

在自我认知 Tab 顶部提供“添加自我认知”按钮。点击后打开轻量弹窗，填写标题，并可在同一个弹窗里逐条添加描述。

保存条件：

- 标题不能为空。
- 创建时写入 `createdAt` 和 `updatedAt`。
- 描述可以为空数组，也可以随标题一起保存。

### 展示

每个自我认知条目以独立卡片展示：

- 标题。
- 描述数量。
- 前几条描述摘要。
- 编辑和删除入口。

当描述为空时，展示一行克制的空状态文字，例如“还没有描述”。

### 编辑与删除

自我认知标题支持编辑。点击编辑后复用添加弹窗，在弹窗内修改标题、添加描述、编辑描述或删除描述。

删除自我认知条目需要确认，因为会连同其描述一起删除。

## 描述交互

### 添加描述

添加描述只发生在自我认知添加/编辑弹窗中。弹窗底部提供描述文本输入区：

- 描述文本输入框。
- 添加按钮。

保存条件：

- 描述文本不能为空。
- 手动页面新增的描述自动写入当前日期，不提供日期选择器。
- 手动页面新增的描述自动写入 `source: 'manual'`，不提供来源选择器。

添加成功后清空描述文本。

### 编辑描述

每条描述支持原位编辑：

- 文本。

保存时更新描述的 `updatedAt`，并同步更新所属自我认知的 `updatedAt`。

### 删除描述

描述删除第一阶段可以直接删除，不弹确认。删除后同步更新所属自我认知的 `updatedAt`。

## 存储与事件

所有自我认知数据变化都需要：

- 写入 `lumostime_self_beliefs`。
- 调用 `updateLocalDataTimestamp()`。
- 派发 `selfBeliefLibraryChanged` 事件。

后续接入备份/导入时，再将 `lumostime_self_beliefs` 纳入主备份 payload。

## UI 风格

延续原则库当前的白底、石色、编辑型页面风格。避免把自我认知做成过重的 dashboard。

按钮使用现有 lucide 图标：

- 添加：`Plus`
- 编辑：`Edit2`
- 删除：`Trash2`

描述列表应紧凑，避免每条描述都做成大卡片。推荐在自我认知卡片内使用轻量行和分隔线。

## 错误与边界

- localStorage 解析失败时返回空数组，并在下一次保存时修复。
- 空标题不允许保存。
- 空描述文本不允许保存。
- 删除自我认知时必须确认。
- 删除描述不需要确认，但后续可以补撤销。

## 测试策略

第一阶段可优先做手动 smoke test：

- 切换原则 / 自我认知 Tab。
- 新增自我认知。
- 在添加/编辑弹窗中添加多条描述。
- 编辑描述文本。
- 删除描述。
- 编辑自我认知标题。
- 删除自我认知并确认。
- 刷新页面后数据仍存在。

如补自动化测试，重点覆盖存储 helper：

- normalize 空值和坏 JSON。
- add/update/delete 自我认知。
- add/update/delete description。

## 后续扩展

后续 AI 接入时，可以新增：

- `self_beliefs` 本地查询 target。
- `create_self_belief` toolCall。
- `add_self_belief_description` toolCall。
- AI 对话中的“已添加自我认知 / 已添加描述”应用结果卡和撤销。

这部分不进入第一阶段实现范围。
