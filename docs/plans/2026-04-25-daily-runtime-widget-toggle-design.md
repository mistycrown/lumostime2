# DAILY_RUNTIME 多尺寸切换组件设计

## 背景

现有 `DAILY_RUNTIME` 小组件本质上是 `4x3` 尺寸，展示一天 24 x 6 的热力图，并默认按一级标签着色，底部展示一级标签图例。

本次需要扩展为两种尺寸并支持点击切换视图：

- `4x3`：保留标题、状态、热力图、图例。
- `4x2`：保留标题、状态、热力图，去掉图例。

两个尺寸都需要支持点击热力图，在“一级标签视图”和“二级标签视图”之间切换。`4x3` 切换时图例也要同步切换；`4x2` 不显示图例，但热力图颜色仍要切换。

## 设计结论

采用“双视图 payload + 原生按实例保存显示模式”的方案。

### 数据层

React 侧一次性构建两套热力图数据：

- `categoryView`
  - 按一级标签聚合
  - 用一级标签名称、颜色、图例
- `activityView`
  - 按二级标签聚合
  - 用二级标签名称、颜色、图例

统一同步到原生侧，避免点击后再回到 Web 层重新计算。

### 原生状态

原生侧为每个 `appWidgetId` 保存当前显示模式：

- `category`
- `activity`

这样每个桌面实例都能独立切换，不会互相影响。

### 渲染层

将 `DAILY_RUNTIME` 渲染器抽成可配置形式：

- 支持不同位图尺寸：`4x3` / `4x2`
- 支持是否显示图例
- 根据当前显示模式选用 `categoryView` 或 `activityView`

### 交互

- 标题区域维持打开 App 的行为。
- 热力图区绑定点击切换行为。
- 点击后直接切换该 widget 的显示模式，并刷新对应实例。

## 实现范围

- 扩展 TS bridge 类型与构建 payload 的逻辑
- 扩展 Android 原生模型、存储与 JSON 解析
- 新增 `4x2` DAILY_RUNTIME provider / layout / provider xml / manifest 注册
- 更新现有 `4x3` DAILY_RUNTIME provider，使其支持点击切换
- 更新刷新协调器，覆盖两个 DAILY_RUNTIME 尺寸

## 验证重点

- `4x3` 默认一级标签着色，点击热力图后切到二级标签着色和二级图例，再点切回
- `4x2` 默认一级标签着色，点击热力图后切到二级标签着色，再点切回
- 同时放置多个同类 widget 时，各自切换状态独立
- 标题点击仍可打开 App
