# 标签删除与关联数据迁移设计

## 背景

当前标签管理中的删除操作只会从分类结构中移除 `Activity` 定义，不会处理历史日志、待办或配置中的标签 ID。这会产生孤立引用：历史记录仍保存旧 `activityId`，待办无法解析关联标签，自动规则和其他配置也会继续保存无效 ID。

## 目标

将标签删除设计为“迁移并删除”：用户删除一个标签时，必须选择一个未归档的替代标签；系统先把所有引用旧标签的记录和配置迁移到替代标签，再删除旧标签。

本次范围只针对二级活动标签（`Activity`）。分类删除保留现有能力，另行设计。

## 用户流程

1. 用户在 `BatchManageView` 点击活动标签的删除按钮。
2. 系统打开“迁移并删除标签”弹窗，展示源标签名称、所属分类和引用影响统计。
3. 用户从下拉框选择替代标签。候选项只包含未归档标签，排除源标签，允许跨分类选择。
4. 弹窗明确说明：历史记录、关联待办、当前会话及所有支持的标签配置都会迁移；跨分类迁移时，日志和待办的关联分类 ID 也会同步改为替代标签所属分类。
5. 用户点击“迁移并删除”后，按钮进入处理中状态，禁止重复提交。
6. 迁移完成后删除源标签，关闭弹窗并显示迁移摘要；取消则不改变任何数据。

即使源标签没有引用，也保持相同流程，仍要求选择替代标签，避免删除语义因数据量不同而分叉。

## 迁移范围

统一操作接收 `sourceActivityId` 和 `targetActivityId`，并扫描所有当前数据状态和独立本地存储配置：

### 核心数据

- `Log.activityId` 替换为目标 ID。
- `Log.categoryId` 替换为目标标签所属分类 ID。
- `TodoItem.linkedActivityId` 和 `linkedCategoryId` 同步替换。
- 子待办继承的标签字段保持与父待办现有继承规则一致。
- `ActiveSession.activityId`、`categoryId`、`activityName`、`activityIcon` 和 `activityUiIcon` 同步更新。

### 规则与配置

- `AutoLinkRule.activityId`。
- 应用自动记录和应用感知规则中的活动 ID。
- `AchievementRule.targetIds` 中属于活动目标的旧 ID；替换后去重。
- 场景卡片动作、快捷入口和相关小组件中的 `activityId`、`categoryId`。
- 设置中的 `relatedTagIds`、AI 日志提交触发标签等活动 ID 数组；替换后去重。
- 其他以 `activityId` 或 `linkedActivityId` 持久化的配置，统一纳入迁移服务，避免只修复已知页面。

不修改日志的标题、备注、属性值、时长或待办的其他业务字段。

## 架构

新增统一的迁移操作，建议放在数据/领域服务层，由上层上下文提供当前状态和持久化回调。`BatchManageView` 只负责弹窗、目标选择、影响预览和确认，不直接更新日志、待办或设置。

迁移操作应提供两个阶段：

- `previewActivityReferenceMigration(sourceId)`：只读扫描并返回各数据源的引用计数。
- `migrateActivityReferences(sourceId, targetId)`：校验、构造完整的新状态并统一提交，返回迁移统计。

这样可以保证预览数字与实际迁移使用同一套扫描逻辑，并便于后续增加新的引用类型。

## 校验与原子性

执行前必须确认：

- 源标签存在；
- 目标标签存在且 `isArchived !== true`；
- 源目标 ID 不相同；
- 目标标签所属分类仍然存在。

迁移采用“先计算、后提交”策略：先在内存中构造所有新状态并完成一致性校验，随后按统一提交流程持久化；只有所有状态准备成功后才从分类结构中移除源标签。任何读取、校验或持久化错误都不得删除源标签，也不得向用户报告成功。

## 交互文案与反馈

弹窗标题：`迁移并删除标签`

确认提示：`删除“源标签”后，历史记录、待办和相关配置会全部关联到“替代标签”。此操作不可自动撤销。`

跨分类提示：`日志和待办的关联分类将同步改为替代标签所属分类。`

成功反馈包含实际迁移数量，例如：`已迁移 126 条记录、8 个待办和 5 项配置，并删除“源标签”。`

## 测试

- 日志同时更新 `activityId` 和 `categoryId`。
- 待办同时更新 `linkedActivityId` 和 `linkedCategoryId`。
- 当前活动会话同步更新名称、图标和分类。
- 单值规则正确替换旧 ID。
- 数组规则替换后不产生重复目标 ID。
- 场景、小组件、应用规则、成就规则、筛选器和 AI 触发配置均能迁移。
- 归档标签不能作为替代标签。
- 源标签和替代标签相同会被拒绝。
- 无引用标签可以迁移并删除。
- 迁移失败时保留源标签和全部原始引用，不产生部分成功状态。
- `BatchManageView` 正确展示预览计数、禁用无效确认并显示成功摘要。
