# 自定义属性统计卡片编排设计

## 状态

设计已确认，图表视觉方案待独立的图表设计智能体输出后再补充。本文只确定统计卡片的产品行为、数据结构、持久化和实现边界。

## 目标

将标签详情页现有的属性统计改造成可编排的统计卡片集合：

- 每张卡片绑定一个自定义属性或“备注”数据来源，以及一种与来源类型匹配的图表类型。
- 每个属性自动拥有一张默认卡片，保持当前统计能力不丢失。
- 同一个属性允许添加多张不同类型的卡片。
- 时间范围、次数/时长等筛选项移动到卡片内部，卡片之间互不影响。
- 用户可以在属性页右上角通过“管理”新增、删除、恢复默认卡片并调整顺序。
- 配置保存在 Activity 上，跨页面刷新、导入导出和同步后保持一致。

## 范围

### 第一阶段包含

- 标签详情页“属性”页右上角的“管理”入口。
- 独立弹窗或抽屉形式的卡片管理界面。
- 卡片新增、删除、上移、下移和恢复默认卡片。
- 首次打开时为旧活动自动补齐默认卡片。
- 新增属性时自动创建默认卡片。
- 卡片级时间范围切换。
- 单选/多选卡片级“次数 / 时长”切换。
- 文本、数字、单选、多选四类属性的默认统计卡片。
- 对条件属性沿用现有按上级选项拆分的统计口径。
- 属性、选项改名和归档后的历史数据兼容。

### 第一阶段不包含

- 跨活动或全局统计面板。
- 多属性交叉分析、相关性分析和公式计算。
- 用户自定义计算字段或聚合脚本。
- 卡片拖拽排序。
- 卡片自定义标题、主题色和自由布局尺寸。
- 图表的最终视觉稿、配色、图形细节和动效方案。这些内容由独立图表设计任务确定。

## 数据模型

在 `src/types.ts` 中增加统计卡片类型，并在 `Activity` 上增加可选配置：

```ts
export type ActivityStatisticCardType =
  | 'textCloud'
  | 'numberTrend'
  | 'numberKpi'
  | 'choiceBar'
  | 'choiceDonut';

export type ActivityStatisticRange = 'all' | '7d' | '30d' | 'year';
export type ActivityStatisticMetric = 'value' | 'count' | 'duration' | 'average' | 'sum';

export interface ActivityStatisticCard {
  id: string;
  source: ActivityStatisticCardSource;
  chartType: ActivityStatisticCardType;
  range: ActivityStatisticRange;
  metric: ActivityStatisticMetric;
  order: number;
}

export type ActivityStatisticCardSource =
  | { type: 'attribute'; attributeId: string }
  | { type: 'note' };

export interface Activity {
  // existing fields...
  statisticCards?: ActivityStatisticCard[];
}
```

约束：

- 自定义属性来源保存属性 ID，不保存属性名称，属性改名后卡片自动显示新名称；备注来源使用稳定的 `type: 'note'`，不依赖虚拟属性 ID。
- `chartType` 只保存稳定的语义类型，不将 SVG、布局或颜色信息写入数据。
- `range` 和 `metric` 属于卡片本身，不再由 `ActivityAttributeStatistics` 共享页面级状态控制。
- `order` 在保存时重新规范化为从 0 开始的连续序号。
- 读取未知或损坏的来源、卡片类型时跳过该卡片，并保留其他有效卡片；不能阻塞属性页加载。
- 对旧数据保持 `statisticCards` 可选，不能要求历史 JSON 必须立即迁移。

## 属性类型与图表能力矩阵

管理界面只能显示与所选属性类型匹配的图表类型：

| 属性类型 | 默认卡片 | 可新增卡片 |
| --- | --- | --- |
| 文本属性 | `textCloud` 词云 | 暂无其他类型 |
| 数字 | `numberTrend` 数值趋势 | `numberKpi` 数值概览 |
| 单选 | `choiceBar` 选项分布 | `choiceDonut` 环形图 |
| 多选 | `choiceBar` 选项分布 | `choiceDonut` 环形图 |
| 备注 | 不自动生成 | `textCloud` 词云 |

图表设计智能体需要分别为以上类型提供多个候选视觉方案，但实现层只依赖这些稳定的 `chartType` 枚举。后续若增加新图表，应扩展能力矩阵和渲染注册表，不改变已有卡片数据含义。

## 默认卡片生命周期

### 默认映射

- 文本属性自动创建一张词云卡片。
- 数字属性自动创建一张数值趋势卡片。
- 单选属性自动创建一张选项条形分布卡片。
- 多选属性自动创建一张选项条形分布卡片。
- “备注”不是属性定义，不自动创建默认卡片；用户可在管理界面中把备注作为文字来源，添加一张 `textCloud` 词云卡片。

### 首次打开旧活动

属性页加载活动时执行纯函数式的 `ensureStatisticCards(activity)`：

1. 读取未归档和已归档属性，按属性定义顺序处理。
2. 保留所有合法的已有卡片及其顺序、时间范围和统计维度。
3. 对没有任何关联卡片的属性补建一张默认卡片；不为备注来源补建默认卡片。
4. 对关联属性已删除但卡片仍存在的配置，清理该卡片并保存一次；备注来源不受属性删除影响。
5. 只有发生实际变化时才调用 `onUpdateActivity`，避免首次渲染产生循环保存。

旧活动首次打开后，已有数字、单选、多选和文本属性都会立即得到对应统计卡片。

### 新增、删除和归档属性

- 新增属性成功后，立即追加对应默认卡片。
- 删除属性时一并删除关联卡片，避免产生无法配置的孤儿卡片；备注来源卡片保留。
- 归档属性不删除卡片；历史日志仍参与统计，卡片可继续展示。
- 归档属性不应作为新增卡片的默认候选，但管理界面可以明确标记其为已归档，并允许用户删除关联卡片。
- 属性类型变更若未来开放，必须重新校验关联卡片；本阶段属性类型不可编辑，避免隐式改变统计语义。

## 统计口径

卡片渲染复用当前属性统计工具和日志筛选逻辑，不重复实现一套数据解释。自定义属性来源沿用现有属性统计口径；备注来源使用每条日志的 `note` 文本：

- 时间范围按日志 `startTime` 使用本地日期计算，支持全部、近 7 天、近 30 天、本年。
- 数字卡片使用数字属性值；趋势卡按日期聚合，KPI 卡提供与现有数字统计一致的汇总指标。
- 单选/多选卡片按选项聚合；次数模式沿用现有计数规则，多选的每个选项分别计 1 次。
- 时长模式使用日志完整时长；多选的每个选项分别计入该日志完整时长。
- 文本词云沿用现有分词、停用词过滤和词频统计逻辑。
- 备注词云只读取日志 `note`，不读取属性值，也不把备注名称当成属性名称；空备注、纯标点和停用词不会产生词频。
- 备注词云按日志时间范围过滤，词频每条日志按现有文本统计规则计数；同一日志的文本不会因为时长而重复加权。
- 条件属性仍按上级单选选项拆分上下文，禁止把不同上下文或不同单位的数字混合汇总。
- 属性或选项被删除后，历史值继续显示为“已删除属性”或“已删除选项”，不静默丢失统计数据。
- 当前卡片没有数据时显示卡片级空状态，不影响其他卡片渲染。

## 属性页交互

### 默认展示

属性页加载后按 `statisticCards.order` 渲染卡片。属性定义存在但没有日志值时，默认卡片仍可显示空状态；不应自动隐藏或删除用户配置。

页面级不再展示统一的时间范围和次数/时长控件。页面顶部保留标题、记录概览和右上角“管理”按钮即可。

### 卡片内部控件

每张卡片根据自身类型显示必要控件：

- 时间范围分段控件放在卡片头部或工具区，仅改变当前卡片。
- 单选/多选卡片显示次数/时长切换；数字和文本卡片不显示无关切换。
- 卡片标题由当前来源名称和图表类型动态生成，例如“体重 · 数值趋势”“备注 · 词云”。不保存标题文本，避免属性改名后出现旧标题。
- 空状态、加载状态和异常状态都限制在卡片边界内。
- 控件需要有可访问的 `aria-label`，小屏下不能导致横向页面溢出。

## 管理弹窗 / 抽屉

点击右上角“管理”后打开独立弹窗或抽屉，关闭后回到属性页。管理界面包含：

- 当前卡片列表，按展示顺序排列。
- 每行显示属性名、图表类型和归档状态。
- 上移、下移按钮；首项上移和末项下移禁用。
- 删除按钮；删除只删除卡片配置，不删除日志或属性数据。
- “新增卡片”入口：先选择自定义属性或“备注”来源，再只显示该来源类型支持的图表类型；备注只显示词云。
- “恢复默认卡片”操作：为缺失默认卡片的属性补建默认卡片，已有卡片不重复覆盖；需有明确确认或可撤销反馈。
- 没有可用属性时显示空状态，并保留关闭入口。

管理弹窗保存策略建议即时保存：每次新增、删除或排序后通过已有 `onUpdateActivity` 更新 Activity。关闭弹窗不应丢失已完成操作。若父级保存失败，沿用现有错误提示机制，不在卡片组件内复制存储逻辑。

## 组件与代码边界

建议拆分为以下职责，具体文件名可在实施计划中调整：

- `activityStatisticCardUtils`：默认卡片、来源能力矩阵、配置清洗、排序规范化和迁移函数。
- `ActivityAttributeStatistics`：读取规范化后的卡片并负责卡片编排，不再持有页面级统计筛选状态。
- `ActivityStatisticCard`：单张卡片的统一外壳、局部控件和状态边界。
- 按 `chartType` 拆分的渲染组件：复用现有词云、数字趋势和选项分布计算逻辑。
- `ActivityStatisticCardManager`：管理弹窗/抽屉，处理增删排序和默认恢复。
- `types.ts`：新增卡片类型与 Activity 配置字段。

不要在图表组件中直接修改 Activity；所有配置变更由管理组件或属性页统一向上提交。

## 兼容、导入导出与同步

- 现有 JSON 导出/导入会随 `Activity` 自动携带 `statisticCards`，无需单独的顶层数据表。
- 旧备份缺少该字段时，读取逻辑按首次打开规则补齐。
- 旧版本卡片若使用 `attributeId` 字段，读取时迁移为 `{ source: { type: 'attribute', attributeId } }`；新建卡片统一使用 `source`。
- 云同步使用现有 Activity 同步链路；卡片配置是普通 Activity 字段，不新增独立同步协议。
- 同一 Activity 在多个窗口同时编辑时，遵循现有最后写入策略；本阶段不实现卡片级冲突合并。
- 非法 `range`、`metric` 或 `chartType` 在读取时清洗为默认值或跳过，不能让整个 Activity 失效。

- 默认映射覆盖文本、数字、单选、多选四种属性类型。

- `ensureStatisticCards` 对旧活动补齐卡片且重复调用幂等。
- 已有卡片的顺序、范围和统计维度在迁移后保持不变。
- 新增属性、删除属性、归档属性分别验证卡片生命周期。
- 图表能力矩阵拒绝不匹配的属性/图表组合。
- 上移、下移、删除和恢复默认卡片保持连续顺序。
- 条件属性、多选时长、已删除选项和空数据卡片保持现有统计口径。
- 卡片级时间范围和次数/时长切换不会影响其他卡片。

### 手动验收

- 为已有活动打开属性页，自动出现每个属性的默认卡片，且只保存一次迁移配置。

- 在管理入口选择“备注”后可添加词云卡；备注卡片只统计日志备注，和文本属性词云相互独立。

- 两张卡片分别设置不同时间范围或统计维度，互不影响。
- 删除属性或选项后，历史日志统计仍可见且显示缺失标记。
- 桌面和窄屏布局下管理弹窗、卡片控件和长属性名不重叠、不溢出。

## 图表设计智能体任务说明（可直接复制的提示词）

下面的提示词用于委托另一个智能体进行 AI 生图和图表视觉设计。它只负责视觉和交互方案，不直接修改本仓库代码，也不自行改变本文已经确认的数据模型。

### 可直接复制给设计智能体的提示词

```text
你是 LumosTime 产品的资深数据可视化设计师和前端设计顾问。请为“活动标签详情页 -> 属性统计”设计一套可落地的统计卡片系统，并使用 AI 生图输出多套候选 UI 视觉稿，供产品方挑选验收。你的任务是设计，不是编写代码；不要擅自增加跨活动分析、公式计算或独立全局仪表盘。

一、产品背景

LumosTime 是个人时间管理与生活记录应用。用户会为一个活动标签定义自定义属性，并在每条时间记录中填写属性值，也可以直接把每条记录的“备注”作为文字数据来源，然后在标签详情页查看统计。例如：
- “健康 / 体重”是数字属性，单位可能是 kg；
- “力量训练 / 锻炼部位”是多选属性，选项可能是胸、背、腿、肩；
- “跑步 / 跑步类型”是单选属性，选项可能是慢跑、间歇、长距离；
- “阅读 / 读后感”是文本属性，统计内容是词频词云。
- “任意活动 / 备注”是内置文字来源，统计内容是日志备注中的词频词云；备注来源不是一个可编辑的自定义属性。

页面不再使用全局时间范围和全局次数/时长控件。每一张卡片自己拥有局部控件，所以同一页面上的不同卡片可以使用不同时间范围和统计维度。用户可以通过右上角“管理”打开弹窗或抽屉，新增、删除、上移、下移卡片并恢复默认卡片。

二、稳定的图表类型

必须围绕以下稳定类型设计，每种类型至少给出 2-3 套明显不同但都可实现的候选方案：
1. textCloud：文本词云。默认用于文本属性。
2. numberTrend：数字趋势。默认用于数字属性，表现日期趋势和数值变化。
3. numberKpi：数字概览。可用于数字属性，表现合计、平均、最小、最大或当前值等关键指标。
4. choiceBar：选项分布条形图。默认用于单选/多选属性，支持次数和时长切换。
5. choiceDonut：选项分布环形图。用于单选/多选属性，支持次数和时长切换。

数据来源有两类：
- 自定义属性：文本、数字、单选、多选，按属性类型匹配图表。
- 备注：内置文本来源，只允许匹配 `textCloud`；不自动生成默认卡片，用户在管理界面主动添加。

不要把最终方案做成营销落地页、海报或大面积装饰图。它必须像一个真实可用的桌面/移动端统计工具，信息密度适中，便于快速比较和长期重复查看。优先使用清晰的卡片层级、细线、留白、局部强调和可读标签；避免卡片套卡片、巨大标题、纯装饰渐变、发光霓虹、离散气泡、无意义插画和过度圆角。

三、必须覆盖的数据场景

请在视觉稿中明确展示或用旁注说明以下情况如何呈现：

数字属性 numberTrend / numberKpi：
- 没有任何记录值；
- 只有 1 个数据点；
- 只有 2-3 个数据点；
- 日期稀疏，中间有很长空档；
- 同一天有多条记录；
- 连续上升、连续下降、基本持平、先升后降；
- 数值跨度很小但需要看出细微变化；
- 数值跨度很大，存在明显离群点；
- 整数、小数、很多小数位；
- 有单位和无单位，例如 kg、公里、下、元、页；
- 数值为 0；
- 允许负数的通用场景；
- 极小值、极大值、平均值、合计值同时出现时，避免视觉混淆；
- 趋势只有一个点时不要画出误导性的折线；
- 近 7 天、近 30 天、本年、全部四种范围标签过长或空间不足。

单选/多选 choiceBar / choiceDonut：
- 没有选项数据；
- 只有 1 个选项；
- 2-3 个选项且分布均匀；
- 选项很多（10、20 个以上）；
- 一个选项占绝大多数，其他选项很小；
- 所有选项数值相同；
- 选项名称很长、包含中文、英文、数字、括号或换行；
- 选项名称重复或相似；
- 选项被归档但历史记录仍有数据；
- 选项已经删除，历史数据显示“已删除选项”；
- 多选统计的选项百分比合计可能超过 100%，不能误导为互斥占比；
```
