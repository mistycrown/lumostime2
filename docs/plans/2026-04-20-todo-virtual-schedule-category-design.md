# 待办虚拟排期分类设计
日期：2026-04-20

## 目标
- 在待办列表页左侧边栏新增一个始终置顶的虚拟分类。
- 该虚拟分类用于查看今天、明天、本周的任务。
- 时间命中范围纳入 `Arrange`、`Due`、循环任务，规则与现有待办排期逻辑保持一致。
- 页面初次进入待办列表时默认落在这个虚拟分类，视觉保持现有极简印刷风格。

## 方案对比

### 方案 A：边栏里拆成三个虚拟分类
优点：
- 结构直接，一眼能看到今天、明天、本周三个入口。

缺点：
- 侧边栏会变长，挤压真实分类。
- 与现有待办页的“一个分类对应一个内容区”节奏不够统一。

### 方案 B：一个虚拟分类，内容区内再切今天 / 明天 / 本周
优点：
- 侧边栏只新增一个入口，改动轻。
- 能保持真实分类列表的阅读节奏。
- 更适合极简印刷风格，顶部做一排轻量时间标签即可。

缺点：
- 多了一层时间切换。

### 结论
采用方案 B。

## 交互设计
- 边栏最上方新增虚拟分类“排期”，位于所有真实分类之前。
- 点击“排期”后，右侧内容区顶部显示 `今天 / 明天 / 本周` 时间标签。
- 默认进入待办页时：
  - 默认选中边栏的“排期”
  - 默认选中时间标签里的“今天”
- 切回真实分类时，仍沿用原有待办列表行为。

## 数据与规则
- 不新增新的持久化分类对象，虚拟分类只存在于视图层。
- 时间范围完全复用现有 `todoScheduleUtils.ts` 中的排期推导规则。
- 命中条件：
  - `scheduledDate` 命中目标日期
  - `deadlineDate` 命中目标日期
  - `recurrenceRule` 在目标日期成立
- “本周”使用当前周的周一到周日。
- 若同一日期同时命中 `Due` 和 `Arrange`，沿用现有规则：列表标签中优先显示 `Due`。

## 列表展示
- 虚拟分类下仍然复用原待办列表项组件，不新建独立卡片体系。
- 在待办标题下方补充一组轻量排期标签，例如：
  - `今天 Due`
  - `明天 Arrange`
  - `周四 Repeat`
- 标签样式采用浅底、细边框、小字距，和当前页面的石色系极简排版保持一致。
- 当本周命中标签过多时，最多展示前 4 个，剩余数量折叠成 `+N`。

## 默认新增行为
- 当用户停留在虚拟分类下点击新增待办时，新增入口仍需落到真实分类。
- 第一版直接回退到第一个真实待办分类作为默认分类，避免改动详情弹窗流程。
