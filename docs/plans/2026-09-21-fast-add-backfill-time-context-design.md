# 快速添加补记时间上下文设计

## 目标

让“快速添加补记”链路能够理解“刚才做了……”这类相对时间表达。快速补记请求需要同时携带当前本地时间和目标日期的时间轴摘要，使 AI 能判断“刚才”对应的结束时间，并参考当天已有记录推断合理的起始时间。

## 方案

在现有 `requestQuickAddBackfillWithDebug` 请求中增加结构化时间上下文：

- `currentDateTime`：发送请求时的本地日期时间，作为“刚才/刚刚/刚结束”的时间锚点。
- `todayTimelineSummary`：按开始时间排序的目标日期日志摘要，包含时间范围、分类/活动和备注。
- 提示词明确相对时间规则：相对当前时间的表达优先落到当前日期；起始时间优先参考最近记录结束时间或当天空档；无法确定时保留字段为空。

发送端继续使用现有 `resolveQuickAddBackfillToolCall` 做日期、时间格式校验和最终兜底。AI 没有返回有效时间时，当前日期仍回退到目标日期，时间仍回退到最近一小时；历史目标日期不会被当前时间强行覆盖。

## 数据流

1. 快速补记发送时读取同一份日志状态，构造目标日期的时间轴摘要。
2. 将当前时间、摘要和用户补记描述传给快速结构化请求。
3. AI 返回 `create_log` 工具调用。
4. 应用端校验并补齐缺省日期/时间，再复用现有日志写入和撤销流程。

## 验证

- 测试请求 prompt 包含当前时间和时间轴摘要，并保留原有词典内容。
- 测试“刚才做了……”在没有明确时间时仍能经过应用端兜底落地。
- 运行相关 Vitest 测试和 `npm run build`。
