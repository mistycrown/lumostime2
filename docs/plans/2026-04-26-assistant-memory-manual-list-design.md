# 长期记忆手动维护列表设计

日期：2026-04-26

## 目标

- 让用户可以在 AI 面板的“长期记忆”里手动维护 `用户画像记忆` 与 `偏好记忆`。
- 把这两个区块从黑底 JSON 调试视图改成可读、可操作的笔记列表。
- 支持新增与删除，但本轮不支持编辑已有条目。
- 继续复用现有 `assistantMemoryService` 持久化逻辑，不改动其他 memory 字段的写入策略。

## 非目标

- 本轮不改 `状态摘要`、`工作记忆摘要`、`活跃 reminders`、`最近 agent 决策` 的展示方式。
- 本轮不支持手动编辑 `recentDecisions`、`activeReminders`。
- 本轮不支持拖拽排序、批量删除、搜索、标签化等扩展能力。

## 需求结论

用户确认的交互结论如下：

- 只开放 `用户画像记忆` 与 `偏好记忆` 两类手动维护。
- 展示方式改成“笔记列表”，每条记忆单独占一行，可容纳稍长文本。
- 需要支持新增与删除。
- 不再使用黑色 `pre` / JSON 调试框展示这两类记忆。

## 方案选择

### 方案 A：两张独立的可维护笔记卡片

- `用户画像记忆` 与 `偏好记忆` 各自独立成卡片。
- 每张卡片展示条目列表、`新增一条` 入口、单条删除按钮。

优点：

- 分类清晰，最符合当前信息结构。
- 新增与删除时不需要先做类型判断。
- 视觉上可以直接替代现有黑底调试块。

缺点：

- 相比纯只读视图，卡片内交互元素更多。

### 方案 B：统一记忆列表，条目带分类

- 两类记忆合并到同一列表。
- 每条记忆显示所属分类。

优点：

- 整体感更强。

缺点：

- 新增时需要额外选择分类。
- 删除后也更难快速扫描剩余内容。

### 方案 C：保留当前结构，仅将 `pre` 改成白底列表

优点：

- 改动最小。

缺点：

- 依然保留明显的“调试面板”气质。
- 对“长期记忆可维护”的产品感提升有限。

### 结论

采用方案 A。

## 交互设计

### 展示

- `用户画像记忆` 与 `偏好记忆` 改为白底卡片。
- 每条记忆单独一行，支持自动换行。
- 空状态显示 `暂无记忆`。

### 新增

- 每张卡片顶部提供 `新增一条` 按钮。
- 点击后，在当前卡片内展开输入区。
- 输入区包含：
  - 多行文本输入框
  - `保存`
  - `取消`

保存规则：

- 输入内容先 `trim`。
- 空文本不允许保存。
- 如果与现有条目完全重复，则不给重复写入，并提示用户。
- 保存成功后刷新长期记忆快照并显示成功 toast。

### 删除

- 每条记忆右侧提供删除按钮。
- 点击删除后，该行切换成轻确认状态：
  - `确认删除`
  - `取消`
- 删除成功后刷新长期记忆快照并显示成功 toast。

## 数据与状态设计

### 数据层

继续复用 `assistantMemoryService`，但新增两个窄 helper：

- 追加一条 `profileMemory` / `preferenceMemory`
- 删除一条 `profileMemory` / `preferenceMemory`

约束：

- helper 只服务于这两类字符串列表。
- 追加逻辑继续复用现有 `applyPatch()` 去重能力。
- 删除逻辑直接基于当前持久化 memory 快照过滤对应字符串后再保存。

### 组件本地状态

在 `AIBackfillChatModal.tsx` 的长期记忆弹层内新增本地 UI 状态：

- 当前展开新增输入框的记忆分类
- 各分类输入草稿
- 当前处于删除确认态的条目

这些状态只用于展示层，不写入长期 memory。

## 文件改动

### `src/types/assistant.ts`

- 新增可手动维护的长期记忆 key 类型，避免组件与 service 写死字符串。

### `src/services/assistantMemoryService.ts`

- 新增手动追加 / 删除长期记忆字符串条目的 helper。
- 保持现有 patch 语义不变。

### `src/services/assistantMemoryService.test.ts`

- 补充追加、去重、删除等测试。

### `src/components/AIBackfillChatModal.tsx`

- 将 `用户画像记忆` 与 `偏好记忆` 改成可读型笔记列表。
- 增加新增输入区、删除确认交互、成功/重复/空输入提示。
- 保持其余 memory 区块原样。

## 风险与控制

### 风险 1：组件自行拼装 memory，造成逻辑分散

控制方式：

- 通过 `assistantMemoryService` 新 helper 收口追加 / 删除逻辑。

### 风险 2：UI 与持久化快照不同步

控制方式：

- 所有新增 / 删除成功后都调用现有 `refreshAssistantMemorySnapshot()`。

### 风险 3：误删

控制方式：

- 采用行内二次确认，不直接一键删除。

## 验证

至少验证以下场景：

1. 能在 `用户画像记忆` 中新增一条文本。
2. 能在 `偏好记忆` 中新增一条文本。
3. 重复文本不会被重复写入。
4. 空文本不能保存。
5. 能删除指定条目，且不会影响另一类记忆。
6. 长期记忆弹层关闭再打开后，新增与删除结果仍然存在。
