# 活动标签自定义属性设计

日期：2026-08-24

## 目标

让用户能为单个活动标签定义可选的结构化属性，并在开始专注、添加补记和编辑记录时填写。属性数据要能在活动标签详情中提供基础统计，同时支持用户后续调整属性和选项名称而不破坏历史语义。

## 范围

- 属性只定义在具体 `Activity` 上；`Category` 不提供定义或继承。
- 支持文本、单选、多选、数字四种属性类型。
- 所有属性均为可选，不阻塞开始专注、结束专注或保存补记。
- 开始专注与添加补记使用同一套属性字段交互，并让属性和标签、领域、备注同级向下排列。
- 活动标签详情提供基础属性统计：数字汇总、单选分布、多选覆盖率。
- 文本属性本期只负责记录与展示，不提供聚合统计、词云或检索。

## 非目标

- 不支持 Category 属性或跨标签继承。
- 不支持属性必填、默认值、条件显示、选项分组或公式计算。
- 不支持将一种已有属性直接更改为另一种类型。
- 不为文本属性设计统计可视化。

## 数据模型

在共享类型中增加以下概念：

```ts
type ActivityAttributeType = 'text' | 'single' | 'multi' | 'number';

interface ActivityAttributeOption {
  id: string;
  label: string;
  isArchived?: boolean;
}

interface ActivityAttributeDefinition {
  id: string;
  name: string;
  type: ActivityAttributeType;
  options?: ActivityAttributeOption[];
  order: number;
  isArchived?: boolean;
  createdAt: number;
  updatedAt: number;
}
```

`Activity` 增加可选的 `attributes?: ActivityAttributeDefinition[]`。

`Log` 与 `ActiveSession` 增加可选的 `attributeValues?: ActivityAttributeValue[]`：

```ts
type ActivityAttributeValue =
  | { attributeId: string; value: string }
  | { attributeId: string; value: number }
  | { attributeId: string; optionId: string }
  | { attributeId: string; optionIds: string[] };
```

记录只保存属性 ID 和选项 ID，不保存属性名称、类型或选项文字快照。属性定义是展示名称的唯一来源：修改属性名或选项名后，所有历史记录和统计自动显示新名称。

历史数据缺少新字段时，按没有填写任何属性兼容。若导入或旧数据引用已不存在的属性或选项，界面保留其值并显示“已删除属性”或“已删除选项”。

## 属性定义管理

在标签详情的“细节”Tab 增加“属性”区块，靠近备注模板、关键词等活动配置：

- 用户可新建属性，填写名称并选择类型。
- 单选和多选属性可管理一层预设选项。
- 属性创建后类型不可修改；需要改变数据含义或类型时创建新属性。
- 属性和选项均支持改名、拖动排序、归档、恢复。
- 归档属性不出现在新记录表单；归档选项不出现在新的选择器。
- 已被历史记录引用的归档属性和选项仍在历史详情及统计中可见。

归档不会删除记录值，恢复也不需要任何数据迁移。

## 记录表单

抽取共享的 `ActivityAttributeFields` 表单区块，供开始专注、进行中专注编辑、添加补记和编辑既有记录调用。

- 仅在已选择的活动标签有未归档属性时显示。
- 按属性 `order` 由上到下排列，位置和标签、领域、备注等常规字段一致，不新增独立的强制步骤或弹窗。
- 文本属性使用单行输入。
- 数字属性使用数字输入，接受小数和负数。
- 单选为可取消的互斥选择。
- 多选为可取消的多个选择。
- 切换活动标签时，保留新标签仍存在的属性值，清理其余值，避免把不相关的值保存到新标签。
- 编辑既有记录时显示记录所引用的归档属性或归档选项，以保证历史数据可见且可修正。

专注期间属性值写入并持久化到 `ActiveSession`。结束专注时，值随会话写入 `Log`；跨天拆分出的每条实际记录都带有相同属性值。补记和编辑记录则直接读写 `Log.attributeValues`。

## 属性统计

活动标签详情新增“属性统计”Tab。统计仅使用当前 Activity 的实际记录，沿用现有统计口径排除计划时间块，默认覆盖全部历史记录。

- 数字属性显示已填写次数、合计、平均值、最小值、最大值；空值不参与计算。
- 单选属性按选项显示填写次数及其占已填写记录的比例。
- 多选属性按选项显示“包含该项的记录数 / 已填写记录数”的覆盖率。由于单条记录可选多个选项，各项百分比之和可超过 100%。
- 文本属性不显示聚合统计。
- 只有已被记录引用的属性、选项才会在统计中出现；无可统计数据时显示空状态，不绘制零值图表。
- 已归档的属性或选项仍参与统计；不存在的引用归入“已删除属性”或“已删除选项”，防止统计总数被静默丢弃。

## 测试与验证

- 属性定义的创建、改名、排序、归档、恢复，以及仅影响所属 Activity 的隔离性。
- 单选、多选记录只保存 ID；属性或选项改名后，历史记录与统计显示最新名称。
- 切换标签时清除不属于目标标签的属性值。
- 专注会话的本地持久化、结束保存与跨天拆分完整保留属性值。
- 补记创建、补记编辑和旧记录缺少属性字段的兼容。
- 数字统计、单选分布、多选覆盖率，以及计划时间块排除。
- 运行 `npm run build`，并手工覆盖桌面与移动布局下的标签详情、开始专注、补记和历史记录编辑流程。
