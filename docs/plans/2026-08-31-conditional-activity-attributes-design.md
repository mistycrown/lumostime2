# 活动条件属性设计

日期：2026-08-31

## 目标

在一个活动标签内，根据已选择的属性选项，动态展示一组相关的补充字段，并让统计按选项语义归类。该能力适用于运动、饮食、睡眠、阅读、用药等任意活动，而不是为某一种活动建立专门模型。

核心原则：标签仍是扁平的活动分类；条件属性只决定记录表单显示哪些字段，不产生嵌套标签或新的记录类型。

## 使用场景

| 活动 | 选择属性 | 选项 | 条件字段 |
| --- | --- | --- | --- |
| 运动 | 运动类型 | 跳绳 | 次数（下） |
| 运动 | 运动类型 | 跑步、骑行 | 距离（公里） |
| 运动 | 运动类型 | 力量训练 | 组数、重量（kg） |
| 饮食 | 用餐方式 | 外食 | 店名、花费（元） |
| 睡眠 | 睡眠类型 | 夜间睡眠 | 入睡时间、起床时间、睡眠质量 |
| 睡眠 | 睡眠类型 | 午睡 | 时长、醒后状态、睡眠质量 |
| 阅读 | 阅读材料 | 书籍 | 页数 |
| 阅读 | 阅读材料 | 论文 | 篇数、阅读状态 |

一个条件字段可被多个选项复用，例如“睡眠质量”同时关联夜间睡眠和午睡，“距离”同时关联跑步和骑行。

## 范围与边界

- 第一版支持单选属性的选项触发字段，且条件只允许一层；不支持条件字段继续触发第三层字段。
- 一个选项可关联零个、一个或多个条件字段。
- 条件字段可为文本、单选、多选或数字；数字字段支持可选单位文本，例如“下”“公里”“元”“页”“kg”。
- 所有字段保持可选，不能阻塞开始专注、结束专注或保存补记。
- 不支持跨活动复用属性定义、公式计算、必填规则、选项分组或多条件表达式。
- 现有无条件属性继续按原样显示与统计，不需要迁移。

## 配置交互

属性管理仍以普通属性列表为入口。单选属性的每个选项旁提供“填写项”入口：

```text
运动类型
- 跳绳       次数（下）
- 跑步       距离（公里）
- 力量训练   组数、重量（kg）
```

用户不需要编写“如果 A 等于 B 则显示 C”一类规则。新增或编辑字段时，在“显示条件”中选择其上级单选属性和一个或多个选项；选择“始终显示”则它是普通字段。

为保持理解成本，管理界面将条件字段在其上级属性下缩进展示，同时仍允许在属性列表中排序。若删除或归档上级选项，必须提示其关联字段会失去触发入口，并提供“改为始终显示”“改挂到其他选项”“同时归档”三个明确选择。

## 数据模型

在现有 `ActivityAttributeDefinition` 上增加可选配置：

```ts
interface ActivityAttributeDisplayCondition {
  attributeId: string;
  optionIds: string[];
}

interface ActivityAttributeDefinition {
  // 现有字段...
  unit?: string;
  displayCondition?: ActivityAttributeDisplayCondition;
}
```

- `displayCondition` 缺失表示始终显示，确保旧数据与既有属性完全兼容。
- `attributeId` 必须引用同一 Activity 中类型为 `single` 的属性；`optionIds` 至少包含一个有效选项 ID。
- 条件和选项一律保存 ID，而不保存显示文案；改名后历史记录与统计自动采用新名称。
- `Log.attributeValues` 与 `ActiveSession.attributeValues` 延续现有结构，无需嵌套保存。条件是属性定义的表单规则，不改变日志值的格式。

## 记录表单行为

1. 先按属性排序显示所有始终可见字段。
2. 用户选择单选选项后，匹配该选项的条件字段立即显示在上级属性之后。
3. 未满足条件的字段不显示，也不会占用表单空间。
4. 用户切换上级选项时，若原选项专属字段已有值，弹出确认：继续切换会清除这些不再适用的值。确认后才清除，取消则保留原选项和数据。
5. 编辑旧记录时，除当前满足条件的字段外，记录中已有的条件字段值也必须展示，防止配置改动后历史值不可见或无法修正。
6. 归档的上级选项或字段不再用于新建记录；历史记录仍能显示并参与统计。

## 统计口径

统计页以“上级选择项”为上下文组织条件字段，禁止把单位或语义不同的数值混合相加。

```text
运动类型
跳绳：18 条记录
  次数：累计 12,000 下，平均 667 下，日趋势

跑步：8 条记录
  距离：累计 42.6 公里，平均 5.3 公里，日趋势
```

- 上级单选属性仍显示各选项的记录次数与比例。
- 每个条件字段只统计同时满足其显示条件且实际填写了该字段的日志。
- 同一字段关联多个选项时，默认分别在每个选项上下文展示；可在字段详情查看跨选项汇总，但只在单位一致时提供合计。
- 数字字段显示填写次数、合计、均值、最小值、最大值与时间趋势，并始终带上单位。
- 文本、单选、多选字段沿用当前各自的统计方式，但统计样本只包含满足条件的记录。
- 配置或选项被删除后，历史值归入“已删除属性”或“已删除选项”，不允许静默丢失统计数据。

## 校验与迁移

- 新建/更新条件字段时校验上级属性存在、类型为单选、至少关联一个选项，且禁止自引用。
- 第一版禁止依赖另一个条件字段，避免循环和深层链路。
- 旧活动、日志和会话缺少条件配置时按全部字段始终可见处理。
- 导入数据的无效条件不阻止数据读取：界面显示该字段的既有值，并在管理处标记为需要修复的条件。

## 验收标准

- 可为任意活动配置“单选选项 -> 多个字段”。
- 同一字段可被多个选项触发，且只需维护一个定义。
- 表单会即时显示/隐藏字段；切换选项不会静默保留不适用的旧值。
- 专注、补记、编辑记录、跨天拆分和本地会话持久化均保留条件字段值。
- 统计按选择项分组，数字不会跨单位或跨语义合并。
- 改名、归档、删除和旧记录均不造成历史属性值不可见或被静默丢弃。
