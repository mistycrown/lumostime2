# AI 对话 Editorial UI 重构设计
## 背景

当前统一 AI 对话窗口已经具备完整能力：

- 会话历史
- 人设切换与编辑
- 上下文缓存开关
- AI 聊天、补记、待办创建
- 调试视图

但界面层仍然偏“功能堆叠式工具面板”：

- 视觉重心分散，聊天主舞台不够突出
- 历史、人设、调试与主聊天区的语言不统一
- 消息、结果卡片、输入区的层级偏常规 SaaS 风格，缺少发布级产品质感
- 与 Claude 式极简印刷氛围相比，当前页面的“纸感、秩序感、阅读感”不足

用户要求：

- 使用前端优化相关思路，达到发布级水平
- 风格参考 Claude，但不要生硬照搬
- 维持与本库现有暖色、石色、衬线化 UI 的一致性
- 移动端和桌面端不拆成两套设计，统一做一套自适应布局
- 可以对 AI 对话区域内部页面自由重构，但尽量不改核心功能链路

## 目标

- 将 AI 对话窗口升级为完整的“对话工作台”
- 统一主聊天区、会话历史、人设编辑、调试面板的视觉语言
- 建立更强的阅读秩序：聊天优先，其余功能退居辅助层
- 让界面整体更接近 Claude 的极简印刷感，同时保留 LumosTime 的暖石色基底
- 在不改变主要业务行为的前提下完成视觉与布局重构

## 非目标

- 本次不重写 AI 服务逻辑、会话模型或消息存储结构
- 不拆出桌面端和移动端两套完全不同的 UI
- 不新增复杂的人设市场、会话搜索、云同步、消息多选等新功能
- 不调整 AI 补记 / 待办工具调用规则本身

## 方案对比

### 方案 A：Editorial Claude

特点：

- 暖纸底色 + 象牙白内容面
- 衬线标题 + 克制的无衬线功能文本
- ring shadow 与细边框取代厚重阴影
- 对话像阅读页面，附属面板像章节页

优点：

- 最符合用户给出的目标
- 与本库现有暖色石系 UI 最容易衔接
- 能在不大动逻辑的情况下显著提升产品完成度

缺点：

- 需要对 `AIBackfillChatModal` 的渲染结构做较大规模重排

### 方案 B：LumosTime Native Plus

特点：

- 延续现有组件语言，只做更细致的打磨

优点：

- 风险最小
- 与现有页面最统一

缺点：

- 改造感不够强
- 很难达到用户要求的 Claude 式印刷气质

### 方案 C：Dark Editorial Hybrid

特点：

- 纸感主背景 + 局部深色章节切换

优点：

- 视觉戏剧性强

缺点：

- 容易与现有应用整体割裂
- 细节控制成本更高

### 结论

采用方案 A。

## 信息架构

AI 对话区重构为五个稳定层级：

1. `Shell 外壳`
   - 整体暖纸背景
   - 顶部作为安静的工作台页眉

2. `Primary Stage 主对话区`
   - 会话标题、消息流、输入区构成绝对主舞台
   - 宽度收敛，强化阅读感

3. `Session Rail 会话轨`
   - 历史不再是工具列表，而是目录式会话轨
   - 新建、切换、重命名、删除作为次级操作

4. `Persona Studio 人设工作区`
   - 选择与编辑统一为一套“模板 + 编辑台”体验
   - 头像、名字、称呼、提示词、上下文轮数按优先级排布

5. `Debug Ledger 调试账本`
   - 保留完整工程可用性
   - 视觉上改造成附录 / 记录册式面板

交互优先级：

`聊天 > 会话切换 > 人设 > 调试`

## 视觉系统

### 色彩

在本库现有暖石色基础上收敛到一套更接近 Claude 的 palette：

- 页面背景：`#f5f1e8`
- 主内容面：`#fbf8f2`
- 次级暖底：`#f0e8dc`
- 边框：`#e7dfd2`
- 主文本：`#1f1d1a`
- 次文本：`#6b655d`
- 弱文本：`#928a80`
- 品牌强调：`#c46f4f`
- 深色按键：`#2f2b28`

原则：

- 不引入冷灰
- 不用强科技蓝紫
- 重点动作才使用陶土强调色

### 字体

- 标题、区块名、空状态大字：`font-serif`
- 功能文本、标签、按钮、输入内容：沿用当前 UI 字体体系
- 强化“标题像印刷物，功能文字像界面”的对比

### 深度

主要使用：

- 细暖边框
- `0 0 0 1px` ring shadow
- 极轻暖阴影

避免大面积厚投影和玻璃感。

### 消息语言

- 用户消息：更整齐、更克制、更像手写便条
- AI 消息：更适合长文阅读，强调段落秩序
- 工具结果：作为嵌入式结果卡，不做突兀“系统弹框”
- 错误 / 系统消息：保留语义区分，但不跳脱整体色系

## 关键组件改造

### 顶部栏

- 左侧展示当前人格头像、会话标题、辅助说明
- 右侧保留历史、关闭、停止等高频动作
- 按钮统一收敛为暖色小控件

### 消息流

- 强化普通消息、系统消息、错误消息、工具结果的区分
- AI 回复提升段落与留白质量
- 调试入口弱化为附属动作

### 输入区

- 改为“写字台式”输入容器
- 输入框为低对比大圆角纸面
- 上下文开关、发送 / 停止整合到同一操作带

### 历史侧栏

- 强调当前会话选中态
- 会话信息以标题、最近更新时间、最后一句摘要为主
- 重命名 / 删除操作默认弱化

### 人设面板

- 上半区展示人格模板与当前身份卡
- 下半区展示编辑区
- 删除、上传头像、Emoji 编辑按风险和频率分层

### 调试面板

- 结构从“开发弹层”变为“附录账本”
- 每个 section 是独立章节
- 代码块保留高密度，但整体视觉更柔和

## 布局策略

- 使用统一自适应布局，不区分两套设计
- 主聊天区在窄宽度下自然堆叠，在宽宽度下展开更完整的工作台感
- 侧栏和人设 / 调试均保留 overlay 机制，避免影响现有逻辑

## 验证

至少验证以下场景：

1. 空会话状态
2. 普通对话状态
3. AI 请求中与停止状态
4. 工具执行结果卡片显示

6. 人设面板选择、编辑、Emoji、上传、删除确认
7. 调试面板打开、关闭、代码块显示
8. `npm run build` 通过

## 风险与控制

### 风险 1：结构重排导致状态分支遗漏

控制：

- 保留原有状态驱动逻辑
- 优先重写外壳和层次，不先动业务处理函数

### 风险 2：窄宽度下内容拥挤或遮挡

控制：

- 统一做一套自适应骨架
- 让面板在窄宽度下纵向流动，而不是硬塞并列布局

### 风险 3：设置与调试区和主聊天风格断裂

控制：

- 三个区域共用同一套纸感表面、边框、标题体系、按钮规则

### 风险 4：为了美观削弱功能可达性

控制：

- 保留所有关键入口
- 只弱化视觉，不弱化功能能力
