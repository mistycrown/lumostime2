# 成就屏人物成长系统设计

日期：2026-08-09

## 目标

在现有成就屏中增加“人物状态”主面板，把光点瓶扩展为一个固定规则驱动的人物成长系统。

V1 只使用用户配置的固定规则计算属性经验，不引入 AI 直接结算。AI 相关能力只保留未来扩展空间。

## 核心边界

成就系统拆成两个并行账本：

- **光点账本**：现有光点、兑换、收藏和封瓶流程。
- **人物成长账本**：属性经验、属性等级、总经验和总等级。

两套账本共用成就规则的行为匹配逻辑，但生命周期完全独立：

- 封瓶只处理光点，不移动或清除人物经验。
- 砸瓶、兑换和收藏不会减少人物经验。
- 删除属性不会抹除历史经验，只将属性归档并从当前面板隐藏。

## 人物状态入口

在成就屏顶部主视觉区域增加两个模式的切换按钮：

- 光点瓶
- 人物状态

人物状态面板与光点瓶使用完全相同的主视觉区域高度。底部详情区高度和现有成就屏保持一致，详情区展开时人物面板和瓶子一样收起。

## 人物状态 UI

整体参考“人物属性 / CHARACTER PROFILE”档案式布局：

1. 顶部显示人物属性标题、副标题和总等级。
2. 中部显示总经验值、总经验进度条和下一等级累计阈值。
3. 下方显示成长属性列表。
4. 不显示右侧人物头像或人物剪影，释放横向空间。

属性列表行包含：

- 圆形 Lucide 图标。
- 中文名称。
- 英文副标题或用户备注。
- 当前等级。
- 当前等级进度条。
- 当前经验与下一等级累计阈值。

默认提供五个属性：

| 名称 | 副标题 | 图标 | 默认颜色 |
| --- | --- | --- | --- |
| 智识 | INTELLECT | `BookOpen` | 鼠尾草绿 |
| 体魄 | VITALITY | `Dumbbell` | 灰蓝 |
| 意志 | WILLPOWER | `Target` | 砖红 |
| 快乐 | JOY | `Smile` | 芥末金 |
| 友好 | SOCIAL | `MessagesSquare` | 灰紫 |

五个属性是初始预设，不是数量上限。用户可以新增任意数量的自定义属性，也可以编辑、排序、归档属性。

五个属性以内时，列表完整显示。六个及以上时，只让属性列表区域独立滚动；顶部标题和总经验区域保持固定，整个成就屏的高度和比例不改变。

## 属性数据模型

```ts
interface AchievementAttribute {
  id: string;
  name: string;
  subtitle?: string;
  icon: string;
  color: string;
  enabled: boolean;
  isPreset: boolean;
  order: number;
  createdAt: number;
  updatedAt: number;
}
```

图标只持久化 Lucide 图标名称字符串，不保存 React 组件。未知图标使用统一的兜底图标渲染。

属性删除采用归档语义：

- `enabled` 设为 `false`。
- 当前状态面板隐藏该属性。
- 指向该属性的规则自动停用。
- 历史记录保留属性名称快照和经验变化。
- 历史经验继续计入总经验，避免总等级因配置修改下降。

## 规则扩展

现有 `AchievementRule` 保留光点逻辑，并增加可选的属性经验效果：

```ts
attributeEffect?: {
  attributeId: string;
  expPerUnit: number;
};
```

一条规则可以：

- 只产生光点。
- 同时产生光点和属性经验。

V1 一条规则只绑定一个属性，属性经验只允许正向增加并使用整数。

示例：

```text
阅读 30 分钟
→ +1 光点
→ +10 智识经验
```

规则编辑流程：

1. 按现有流程选择标签、领域、筛选器、待办分类或日课组。
2. 配置光点效果。
3. 可选开启“同时增加属性经验”。
4. 选择一个属性。
5. 设置每个命中单位增加的经验值。

## 成长每日快照

人物经验使用独立的每日成长快照，不直接写入光点每日快照：

```ts
interface AchievementGrowthDailySnapshot {
  id: string;
  date: string;
  attributeChanges: Array<{
    attributeId: string;
    attributeName: string;
    deltaExp: number;
    ruleBreakdown: Array<{
      ruleId: string;
      ruleName: string;
      matchedValue: number;
      appliedUnits: number;
      expPerUnit: number;
      deltaExp: number;
    }>;
  }>;
  computedAt: number;
}
```

记录 Tab 合并展示光点每日变化和属性每日变化，但数据层保持两套账本。

## 启用日期和重算

人物成长系统使用独立的 `growthStartDate`，避免用户升级后自动追溯大量旧时间记录。

每日同步时：

- 重算今天。
- 重算昨天。
- 重算最近 7 天。
- 更早的成长快照保持不变。

点击“全部重算”时，从 `growthStartDate` 开始重建全部成长快照，并重新计算所有属性经验、等级、总经验和总等级。

同一天只能存在一条成长快照，重算时覆盖原快照并保留稳定的快照 ID。

## 经验和等级计算

属性总经验：

```text
attributeExp = 所有成长快照中该属性 deltaExp 的总和
```

总经验：

```text
totalExp = 所有属性成长经验的总和
```

经验只增加，不允许因为封瓶、删除属性或修改显示配置而减少。

等级从累计经验推导，不单独保存为可编辑数值：

```text
Lv1 → Lv2：100 XP
Lv2 → Lv3：200 XP
Lv3 → Lv4：300 XP
```

累计等级阈值使用：

```ts
requiredExpForLevel(level) = 50 * level * (level - 1);
```

等级没有上限。界面展示当前等级区间内的进度，以及下一等级的累计经验阈值。

## 记录展示

每日记录折叠态展示：

```text
2026-08-08
光点 +3
智识 +20 · 体魄 +10 · 意志 +5
```

展开后显示：

- 命中的光点规则。
- 命中的属性经验规则。
- 匹配时长、完成数量或日课数量。
- 每条规则产生的光点和经验变化。

“全部重算”按钮的确认文案需要明确说明：光点历史和人物成长历史都会按当前规则重建，封存瓶会被清空并重新生成。

## V1 不包含

- AI 自动产生属性经验。
- AI 每日结算开关和后台定时请求。
- 属性经验扣除。
- 人物装备、技能树和复杂角色动画。
- 属性之间的相互影响。
- 属性数量上限。

未来 AI 可以作为另一种成长记录来源，但不应直接覆盖规则来源的快照。

## 技术接入范围

建议沿用现有结构：

- `AchievementContext` 管理属性、成长快照和计算结果。
- `dataRepository` 增加属性和成长快照的独立持久化入口。
- `achievementUtils.ts` 增加成长快照计算、经验汇总和等级计算工具。
- `AchievementView.tsx` 增加光点瓶 / 人物状态模式切换。
- 新增人物状态展示、属性编辑和属性配置组件。
- `AchievementRulesTab.tsx` 增加可选属性经验效果编辑。
- `AchievementRecordsTab.tsx` 合并展示两类每日记录。

## 测试重点

- 默认五个属性的初始化和持久化。
- 自定义属性新增、编辑、排序和归档。
- 规则同时产生光点和属性经验。
- 规则只产生光点时不生成属性变化。
- 今天、昨天和最近七天重算范围。
- 全部重算后的经验与等级一致。
- 封瓶不会改变属性经验和总等级。
- 删除属性不会删除历史经验。
- 六个以上属性时只有列表区域滚动。
- 经验累计到等级边界时等级正确升级。
