# 沉浸式计时黑白重构设计

## 背景

当前沉浸式计时页面包含主题切换、时钟样式切换、翻页时钟、白噪音选择等多套视觉与交互逻辑，界面顶部共有五个按钮。用户希望将沉浸式计时收敛为单一黑白方案，去掉可配置的视觉样式，只保留必要操作，并让状态栏表现与应用内其他普通页面一致。

## 目标

1. 沉浸式计时页面固定为黑底白字。
2. 计时数字固定使用黑体风格无衬线字体，不再支持主题和时钟样式切换。
3. 去掉翻页时钟效果，仅保留一种数字显示方式。
4. 顶部按钮从五个缩减为三个：返回、提交、白噪音。
5. 状态栏不再在沉浸式模式下隐藏，而是显示为黑色背景并使用浅色图标。
6. 退出沉浸式计时后，恢复应用原有的状态栏托管逻辑。

## 非目标

1. 不修改白噪音的音源、播放逻辑和数据结构。
2. 不改动沉浸式方向锁定逻辑。
3. 不重构 `FocusDetailView` 与沉浸式计时的接入关系。

## 方案选择

### 方案 A：保留现有组件外壳，内部重写为单一黑白样式

优点：

1. 改动集中在沉浸式组件和状态栏工具，接入点最少。
2. 能直接复用现有白噪音、方向锁定、退出/提交回调。
3. 回归风险低，清理冗余逻辑后结构会更简单。

缺点：

1. 需要在现有组件中做一轮较大的删减。

### 方案 B：新建极简沉浸式组件并替换现有入口

优点：

1. 新代码更纯净。

缺点：

1. 需要重新迁移白噪音、状态栏、方向锁定、交互按钮，改动面更大。

### 结论

采用方案 A。保留 `ImmersiveTimer` 组件作为入口，重写其内部视觉和控制层，并同步删除不再使用的主题、时钟样式与翻页实现。

## 架构设计

### 1. 沉浸式计时页面

`src/components/ImmersiveTimer.tsx` 保留如下职责：

1. 处理方向锁定。
2. 处理白噪音播放与切换。
3. 管理控制按钮显隐。
4. 渲染统一黑白计时界面。
5. 管理进入/退出沉浸式时的状态栏行为。

移除如下职责：

1. 主题读取与持久化。
2. 时钟样式读取与持久化。
3. 翻页时钟分支渲染。
4. 主题选择弹窗。
5. 时钟样式选择弹窗。

### 2. 状态栏行为

`src/utils/statusBarTransitions.ts` 从“进入时隐藏状态栏”调整为“进入时显示状态栏，设置黑色背景，并保留恢复托管状态栏的退出行为”。沉浸式页面会在进入时应用黑色状态栏，在退出时调用现有 `statusBarService.updateForBackground(...)` 恢复普通页面状态。

### 3. 冗余文件清理

若无其他引用，删除以下仅服务于旧沉浸式主题系统的文件：

1. `src/components/FlipClock.tsx`
2. `src/components/ImmersiveSelectorModal.tsx`
3. `src/components/immersiveThemes.ts`
4. `src/components/immersiveThemes.test.ts`

## 界面设计

### 视觉

1. 页面背景统一为纯黑或近纯黑。
2. 数字统一为白色，使用黑体风格字体栈，例如 `"Noto Sans SC", "Microsoft YaHei", sans-serif`。
3. 横屏下保持单行大数字显示。
4. 竖屏下仍可拆分小时、分钟、秒，但统一使用同一套黑白样式，不引入主题色。
5. 去掉背景氛围光斑、渐变和文字阴影。

### 控件

1. 返回按钮位于左上。
2. 提交按钮位于返回按钮右侧。
3. 白噪音按钮位于右上。
4. 按钮本身也采用黑白体系，使用半透明深色底与浅色描边。

## 测试策略

1. 先修改 `src/utils/statusBarTransitions.test.ts`，让“进入沉浸式时隐藏状态栏”的旧断言失败。
2. 修改 `statusBarTransitions.ts` 使测试转绿，并补充黑色背景相关断言。
3. 对沉浸式组件运行构建验证，确认删除旧文件后无残留引用。

## 风险与处理

1. 风险：状态栏 API 在不同平台能力不一致。
   处理：保留现有 EdgeToEdge 背景设置辅助函数，只在移动端应用沉浸式状态栏策略。

2. 风险：删除主题系统后可能残留未清理的引用。
   处理：用全局搜索确认 `FlipClock`、`ImmersiveSelectorModal`、`IMMERSIVE_THEMES` 无其他使用点，再删除文件。

3. 风险：横屏大字体可能溢出。
   处理：保留现有字体自适应逻辑，但移除对时钟样式的依赖。
