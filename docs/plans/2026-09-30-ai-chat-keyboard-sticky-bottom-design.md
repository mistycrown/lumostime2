# AI 对话键盘升起时保持最新消息可见：设计

## 背景

移动端 AI 对话输入框获得焦点后，软键盘会压缩可视区域。当前实现只在聚焦后的连续两个动画帧滚动到底部；部分 Android 设备的键盘布局变化晚于这两个动画帧，因此对话内容没有随最终可视高度继续上移，最新消息会被输入区或键盘遮挡。

用户期望：如果对话原本处于默认的底部位置，点击输入框后应继续显示最新消息；如果用户已经向上翻看较早消息，则不能强制跳回底部。

## 方案选择

采用“底部意图锁定 + 尺寸变化跟随”方案：

1. 为对话滚动容器建立 DOM 引用。
2. 输入框聚焦前，根据滚动容器距底部的距离判断用户是否仍在底部附近。
3. 仅当用户原本在底部附近时，开启临时的底部跟随状态。
4. 键盘升起导致对话区域高度变化时，通过尺寸观察再次滚动到消息末尾，不依赖固定延迟或特定输入法动画时长。
5. 用户主动向上滚动、输入框失焦或对话关闭时，取消底部跟随，避免打断历史消息阅读。

未采用的方案：

- 多次定时滚动：实现简单，但依赖设备和输入法动画时序，仍可能偶发失败。
- 原生键盘插件事件：时机明确，但会增加 Capacitor 依赖和平台分支，超出本次修复所需范围。

## 组件与数据流

- `AIBackfillChatConversationPane` 持有实际可滚动消息区，并接收滚动容器引用与滚动事件。
- `useAIBackfillChatViewState` 保存滚动容器引用及“是否应保持底部”的可变状态，避免键盘动画期间引发不必要渲染。
- `useAIBackfillChatViewport` 负责底部距离判断、尺寸监听、滚动跟随与生命周期清理。
- `AIBackfillChatComposer` 在输入框聚焦和失焦时通知视口逻辑，而不是无条件执行固定帧数滚动。

事件顺序：输入框聚焦 → 读取聚焦前的底部状态 → 若在底部则锁定跟随 → 键盘改变布局、滚动容器高度缩小 → 尺寸观察回调滚到最新消息。用户向上滚动时解除锁定，后续尺寸变化不再改变其阅读位置。

## 边界与兼容性

- 底部判断使用小范围像素阈值，允许亚像素舍入和轻微滚动偏差。
- 程序触发的滚动不应被误判为用户离开底部。
- 没有 `ResizeObserver` 的环境保留当前聚焦帧滚动作为降级路径。
- 桌面 AI 小组件和网页端沿用相同逻辑，但只有输入框聚焦且原本位于底部时才会跟随，不改变普通阅读行为。
- 对话关闭或切换时清理观察器和跟随状态，避免跨会话残留。

## 验证

- 单元测试：底部距离判定覆盖位于底部、阈值内和明显离开底部三种情况。
- 单元测试：聚焦时仅对原本位于底部的会话启用跟随。
- 单元测试：用户停留旧消息时，键盘相关尺寸变化不会触发滚到底部。
- 构建验证：运行相关 Vitest 测试及 `npm run build`。
- 移动端冒烟检查：默认进入会话后点输入框，最新消息保持可见；上滑查看旧消息后点输入框，滚动位置不被强制改变。
