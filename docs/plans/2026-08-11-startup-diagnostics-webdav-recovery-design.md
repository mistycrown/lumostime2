# 启动诊断与 WebDAV 恢复保护设计

## 目标

优先解决两类高严重度问题：WebDAV 保护性备份失败后仍允许覆盖本地数据，以及应用启动初始化无限等待。普通业务错误暂不做全量埋点。

## 方案

### WebDAV

- 保护性备份失败时立即返回失败，不再显示“是否继续恢复”的确认框。
- Android 端不自动创建目录；如果 `backups` 目录不存在，保留 HTTP 状态、响应错误、请求 URL，并提示用户手动创建目录。
- Android 下载恢复使用每次请求独立生成的临时路径，避免未定义路径导致二次失败。
- 不在同步失败时自动清空或覆盖本地数据。

### 启动诊断

- 在 React 挂载前初始化可选的 Sentry SDK。
- 持久化启动记录和最近启动阶段：数据仓库、回顾、分类目标、成就。
- 20 秒内未完成启动时上报 `startup_timeout`；下一次启动补报上次未完成的启动。
- 正常进入主界面后记录 `boot_completed` 并取消看门狗。
- 没有 DSN 时保持本地正常运行，不产生网络请求。

## 数据边界

上报版本、平台、阶段、耗时和脱敏后的错误信息；不上传日记、待办、聊天、WebDAV 密码或完整本地存储。

## 验证

- 测试备份目录不存在时的可读错误。
- 测试备份失败不会调用云端恢复。
- 测试 Android 下载临时路径已定义。
- 测试启动超时与正常启动事件。
- 运行相关 Vitest 和 `npm run build`。
