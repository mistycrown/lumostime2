# Todo 进度追踪模式设计

## 背景

当前待办的进度追踪只有“开 / 关”两态：

- 开启后，任务进度来自 `completedUnits`
- 关联记录时，会显示手动填写 `progressIncrement` 的入口
- 子任务系统已经存在，但父任务进度还不能按子任务自动计算

这会导致一个问题：当父任务已经拆成多个子任务后，用户仍需要手动维护父任务进度，记录录入界面也会继续显示手动进度入口，和“按子任务推进父任务”的直觉不一致。

## 目标

- 在任务详情 `细节` 中，把原有进度追踪开关升级为三态切换
- 支持父任务按“已完成子任务数 / 子任务总数”自动计算进度
- 当父任务开启“子任务自动”后，关联记录时不再显示手动添加进度入口
- 不改变现有子任务一层结构与日志模型

## 非目标

- 不支持子任务再拥有子任务
- 不支持按子任务自己的数值型进度折算父任务进度
- 不新增新的日志字段或迁移日志数据
- 不改变现有完成态、排期、循环、专注启动等规则

## 方案对比

### 方案 A：新增明确三态字段

新增 `progressTrackingMode: 'none' | 'manual' | 'subtasks'`。

优点：

- 状态语义清晰，详情页、列表、日志录入都能围绕同一个字段判断
- 便于以后继续扩展新的自动进度来源
- 可以兼容旧数据，并逐步淡化 `isProgress`

缺点：

- 需要补旧数据兼容逻辑

### 方案 B：保留 `isProgress`，再新增 `autoProgressFromSubtasks`

优点：

- 表面改动较小

缺点：

- 状态来自两个字段组合，容易出现非法组合
- UI 条件和保存逻辑会变复杂

### 方案 C：完全不新增字段，靠是否有子任务推断

优点：

- 数据结构改动最少

缺点：

- 无法表达“用户主动选择手动进度还是子任务自动”
- 删除全部子任务后状态会变模糊

## 结论

采用方案 A。

## 数据模型

在 `TodoItem` 中新增：

```ts
progressTrackingMode?: 'none' | 'manual' | 'subtasks';
```

兼容策略：

- 旧数据中 `isProgress === true` 的任务，默认视为 `manual`
- 其他任务默认视为 `none`
- 初期保留 `isProgress` 字段，作为兼容字段继续存在

统一语义：

- `none`：不追踪进度
- `manual`：进度来自 `completedUnits`
- `subtasks`：父任务进度来自直接子任务完成数

## 交互设计

### 任务详情

在任务详情 `细节` 中，将现有“进度追踪”二元开关改为三态切换：

- `关闭`
- `手动进度`
- `子任务自动`

显示规则：

- 普通父任务且没有子任务：只显示 `关闭 / 手动进度`
- 普通父任务且已有子任务：显示 `关闭 / 手动进度 / 子任务自动`
- 子任务：不显示 `子任务自动`

### 子任务自动模式说明

当当前任务为 `subtasks` 时：

- 显示说明文案：进度按已完成子任务自动计算
- 不再允许通过详情页直接编辑父任务的已完成值
- 进度条、百分比、时间线卡片继续复用现有展示样式

### 记录录入

在 `AddLogModal` 中：

- 只有关联任务为 `manual` 时，才显示手动 `progressIncrement` 输入区
- 关联任务为 `none` 或 `subtasks` 时，不显示这块 UI

## 计算规则

### 手动进度

- `completedUnits`：来自日志 `progressIncrement` 的累计写回
- `totalAmount`：用户填写
- 百分比：`completedUnits / totalAmount`

### 子任务自动

仅对父任务生效，且只看直接子任务：

- `completedUnits = 已完成直接子任务数`
- `totalAmount = 直接子任务总数`
- 百分比：`已完成直接子任务数 / 直接子任务总数`

如果没有子任务，不允许选择该模式。

## 状态约束

- 只有父任务可以使用 `subtasks`
- 子任务详情页不显示该选项
- 若父任务当前是 `subtasks`，后来直接子任务被删空，则自动回退到 `none`

## 代码联动

### `TodoDetailModal`

- 进度区域改为三态切换
- 根据模式决定是否显示手动数量输入
- `subtasks` 模式下显示只读说明和自动计算结果

### `AddLogModal`

- 渲染额外进度输入前，判断关联待办是否为 `manual`

### `useLogManager`

- 仅对 `manual` 任务执行 `completedUnits` 的增减写回
- 对 `subtasks` 任务不写回父任务数值

### `useTodoManager`

- 新建待办默认 `progressTrackingMode = 'none'`
- 复制、批量新增、子任务创建时保持合法默认值
- 当父任务失去全部子任务时，若当前为 `subtasks`，自动回退到 `none`

### 进度展示层

新增统一 helper，供列表、详情、时间线、日志摘要等界面复用：

- 判断任务是否应显示进度
- 提供有效的 `completedUnits`
- 提供有效的 `totalAmount`
- 提供当前进度模式

这样可以避免不同页面各自直接读取 `isProgress` 和 `completedUnits`，导致口径不一致。

## 验证清单

1. 无子任务的父任务，只能选择 `关闭 / 手动进度`
2. 有子任务的父任务，出现 `子任务自动`
3. 切换到 `子任务自动` 后，父任务进度随子任务完成数变化
4. 关联该父任务新增记录时，不显示手动进度输入
5. `manual` 任务仍可通过日志继续累计进度
6. 删除最后一个子任务后，父任务自动回退到 `关闭`

## 风险

- 现有仓库大量位置直接使用 `isProgress`，需要统一梳理并逐步收口
- 若只改详情页和录入页，不改列表 / 时间线 / 摘要层，容易出现展示口径不一致
- 旧数据兼容需要确保初始状态稳定，避免历史进度任务突然消失进度条
