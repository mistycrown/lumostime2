# 应用觉察关闭后的前台去重设计

## 问题

在目标应用（例如小红书）前台时点击工作流“关闭”，原生取消逻辑会清空前台应用去重记录。悬浮层关闭后产生的窗口事件随后再次被识别为一次新的应用进入，导致工作流立即重复弹出。

## 方案

取消当前工作流时保留当前目标应用包名的去重记录。应用仍处于前台期间，同一包名的后续窗口事件继续忽略；当无障碍服务确认切换到其他应用时，才更新去重记录。用户离开目标应用后再次返回，目标应用包名发生切换，工作流可以正常再次触发。

该行为同时覆盖原生工作流和 Web 回退工作流，因为二者都通过原生 `cancelAppAwarenessWorkflow` 处理关闭动作。

## 验证

- 原生服务单元级行为：取消后同包名事件不触发重复检测，切换到其他应用后再次返回可以触发。
- 执行前端构建，确保插件接口和 TypeScript 代码无回归。
