# 日报回顾问答节点功能设计

## 目标

让日报回顾问答与 Log 备注使用一致的节点能力：支持括号快速输入、名称/别名匹配建议、点击转为双链，并让日报回答出现在节点详情的关联记录中。同时完善节点合并、重命名同步和结构化 AI 节点简介。

## 范围与现状

- 节点关系目前主要从 `Log.note` 的 `[[节点]]` 双链派生。
- `DailyReview.answers` 保存回顾问题和回答，但尚未进入节点索引。
- Log 编辑已有括号快捷输入和实时匹配建议，可抽出为共享能力。
- 节点合并与重命名已有纯函数入口，需要扩展到日报回答文本。
- 节点简介目前由 AI 返回一段纯文本，会覆盖编辑器中的现有简介。

## 设计

### 1. 日报回答节点输入与索引

文本型回顾问题使用共享的节点文本编辑器，提供：

- 光标处插入/补全 `[[...]]`，支持选中文本包裹。
- 根据当前回答中的节点名称和别名显示匹配建议。
- 点击建议后只替换普通文本，不改写已有双链。

回答仍以 `ReviewAnswer.answer` 持久化，节点链接不另建关系表。节点上下文在构建索引时同时接收日报列表，并为每个节点维护日报回答关联；日报回答按日期和问题显示，点击可回到对应日报的引导页。

### 2. 重命名与合并

- 重命名节点时，更新所有 Log.note 和所有 DailyReview.answers.answer 中指向旧规范名的双链，并把旧名称保留为别名。
- 合并时由用户选择主节点；源节点名称及别名并入主节点别名，简介内容去重后合并；所有 Log 和日报回答中的源节点链接改为主节点链接。
- 保留当前历史导航到主节点，避免合并后停留在已删除节点。

### 3. 关联详情

- 节点详情的“关联”页继续展示相关节点和潜在关联。
- 潜在关联的每条 Log 提供明确的打开详情按钮，复用现有 Log 编辑入口；“关联”操作仍单独保留。
- 已关联 Log 与日报回答分组展示，日报回答入口回到日报详情并定位到引导页。

### 4. AI 节点简介

AI 请求返回结构化对象，而不是自由文本：

- `basicInfo`: `identity`、`relationship` 等字段；无法从记录确认时返回空字符串。
- `bioAdditions`: 可追加到用户简介的事实性补充。
- `recentInteractions`: `{ date, summary }[]`，同日记录可合并。

前端按固定 Markdown 格式渲染：

```md
## 基本信息
- 身份：
- 关系：

## 简介
（用户已有内容原样保留）
（AI 补充追加在已有内容之后）

## 最近交往记录
- 10月7日：……
```

生成前记录编辑版本；若用户在请求期间修改简介，不覆盖用户最新内容。空字段保留标题和空值，不允许 AI 根据不足信息猜测身份、关系、性格或情感。

## 数据流与错误处理

节点关联完全由文本双链派生，避免新增同步冲突的关系表。日报或 Log 更新后由现有数据上下文重新构建索引。无法解析的 AI JSON、空简介或空记录均提示错误并保留现有内容；重命名/合并失败时不修改任何记录。

## 验证范围

- 节点工具函数：日报回答中的重命名、合并、别名匹配、重复链接保护。
- 节点索引：同时返回 Log 与日报回答关联，更新后关系数量正确。
- 回顾输入：括号插入、建议点击、已有双链不重复包裹。
- 节点详情：潜在关联可打开 Log，日报关联可回到日报。
- AI 简介：结构化解析、保留用户原文、同日记录合并、请求期间编辑不被覆盖。
- 运行相关 Vitest 测试并执行 `npm run build`。
