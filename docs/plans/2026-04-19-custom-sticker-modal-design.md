# 自定义贴纸组管理设计

## 背景

当前“设置 -> 投喂小鱼干”中的自定义贴纸组管理存在几个主要问题：

1. 新建贴纸组后，如果组内还没有贴纸，管理区不会显示该组，导致用户误以为没有创建成功。
2. 贴纸组编辑仍然使用内嵌表单，包含不需要的描述字段，和目标交互不一致。
3. 自定义贴纸组使用大卡片管理，和系统内置贴纸组的小方块视觉不一致。
4. 贴纸与贴纸组的删除语义混入归档概念，容易让用户误解“删除”和“归档”的差别。

## 目标

- 新建贴纸组后立即在管理区可见，即使组内没有贴纸。
- 去掉贴纸组描述字段，只保留名称。
- 新建与编辑统一使用垂直居中的模态框。
- 模态框顶部编辑名称，底部展示 16 个固定槽位。
- 点击空槽位上传图片并填充到该槽位。
- 已有贴纸支持单独删除，不影响其他槽位位置。
- 自定义贴纸组在赞助页里改为和内置贴纸组一致的小方块网格。
- 删除前先检测历史引用次数，用户确认后直接删除，不再引入归档流程。

## 方案

### 数据层

- 保留现有 `CustomStickerSetRecord` / `CustomStickerRecord` 结构。
- 继续复用 `sortOrder`，但将它明确作为槽位索引使用，范围为 `0-15`。
- 自定义贴纸视图构建函数增加 `includeEmptySets` 参数：
  - 管理页传 `true`，保证空组可见。
  - 贴纸选择器等消费端保持默认行为，不展示空组。

### 交互层

- 管理区使用统一的小方块网格展示：
  - 第一个方块是带 `+` 的新建入口。
  - 自定义贴纸组使用和内置贴纸组一致的方块预览。
  - 点击自定义贴纸组方块直接打开编辑弹窗。
- 弹窗在新建状态下先输入名称并点击“创建贴纸组”。
- 创建成功后弹窗保持打开，并切换为编辑状态，允许继续上传贴纸。
- 编辑现有贴纸组时直接展示当前名称和 16 个槽位。
- 点击空槽位后打开文件选择器：
  - 单选时占用当前槽位。
  - 多选时从当前槽位开始，依次填入后续空槽位。
  - 不回填点击位置之前的空槽位，避免位置跳动。
- 单张贴纸删除与整组删除都先做引用检测：
  - 仅统计 `dailyReviews` 中 `moodEmoji` 对应的历史贴纸引用次数。
  - 若检测到引用，仅提示引用数量并让用户确认。
  - 用户确认后仍直接删除图片文件与贴纸记录，不再拦截或修复引用。

### 展示层

- 页面上移除原来的自定义贴纸组大卡片和归档区。
- 自定义贴纸组与内置贴纸组并排显示为小方块。
- 新建、编辑、删除都从弹窗进入，页面只保留方块入口。

## 风险与兼容

- 老数据中的 `description` 字段先保留兼容读取，但界面不再编辑和展示。
- 老数据中的 `sortOrder` 会被直接当作槽位索引使用；现有数据本身已按顺序生成，可平滑兼容。
- Mood Picker 继续只展示含贴纸的组，避免出现空白页。
- 历史上若存在 `archived` 贴纸组或贴纸，当前页面不再提供归档管理入口。

## 验证点

- 新建空组后，管理区立即显示该组。
- 自定义贴纸组与内置贴纸组视觉上都使用统一的小方块预览。
- 编辑弹窗始终垂直居中，不再从底部滑出。
- 编辑名称可保存，关闭再打开仍保留。
- 上传贴纸按固定槽位落位。
- 删除某个槽位后，再次上传可填回该槽位。
- 删除贴纸或贴纸组前会提示检测到的历史引用次数。
- 用户确认删除后直接删除贴纸文件和记录，不再归档。
- Mood Picker 与默认贴纸页设置不出现空组空白页。
