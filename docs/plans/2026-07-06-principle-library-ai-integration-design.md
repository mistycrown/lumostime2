# 原则库 AI 集成设计

## 背景

当前原则库是一个静态卡片库，负责保存用户需要反复确认的核心原则。它已经通过 `lumostime_principles` 存在本地，并在设置页提供新增、编辑、删除、重置能力。

本次设计目标是让原则库进入 AI 普通对话工作流，让 AI 在合适的时机读取原则、运用原则、生成新原则，而不是把所有原则长期塞进每次对话上下文。

## 设计判断

采用“融入日常对话 + 按需本地检索 + 结构化写入”的方案。

不新增独立的原则模板对话作为第一阶段主入口。模板对话适合固定流程，例如周复盘；原则库更像长期个人认知系统，应该在普通对话里被 AI 按需调用。

不把原则库常驻注入 AI 上下文。原则内容可能不断增长，每次都注入会增加 token 成本，也会让普通对话被不必要的价值判断干扰。

## 用户体验

### 调用原则

当用户出现以下场景时，AI 可以主动查询原则库：

- 用户难以行动、拖延、焦虑、自我否定。
- 用户需要宏观理论、价值判断或行动鼓励。
- 用户在复盘一段经历，需要把经验提升到原则层。
- 用户明确要求“用我的原则”“原则库怎么看”“帮我从原则角度分析”。

AI 查询到原则后，不机械朗读卡片，而是按以下结构回应：

1. 识别用户当前处境。
2. 连接一条或多条相关原则。
3. 用简洁的心理学/认知框架解释为什么这条原则适用。
4. 给出一个可执行的下一步。

### 添加原则

当用户在对话中完成复盘、经验总结或形成稳定判断时，AI 可以返回 `create_principle` 工具调用。

交互方式对齐现有 AI 生成记录/待办：

- 默认直接保存到原则库。
- 聊天中显示“已添加原则”的应用结果卡。
- 用户可以点击“撤销”删除刚创建的原则。
- AI 不能只用文字声称已保存；必须通过结构化 toolCall 写入。

### 修改原则

原则库列表中的卡片支持进入详情页。详情页允许修改：

- 标题
- 正面文字
- 反面文字

列表上的编辑入口可以保留，但详情页会成为更完整的修改入口。

## AI 能力设计

### 本地查询扩展

在 `localQueryRequest` 中新增原则查询能力：

- 新增 target：`principles`
- 推荐 mode：`keyword_search`
- 当 AI 需要完整原则列表时，允许使用空查询或约定查询词拉取原则库。

查询结果 item 使用统一结构：

```ts
{
  itemType: 'principle',
  id: string,
  title: string,
  summary: string,
  metadata: {
    frontText: string,
    backText?: string
  }
}
```

digest 面向 AI，保持紧凑：

```text
- 1. [principle] 能力是生长的，而非固定的 | 正面：固定思维让人极度渴望证明自己。反面：把挫折看作升级系统的数据反馈。
```

### 工具调用扩展

新增 `create_principle`：

```json
{
  "toolName": "create_principle",
  "args": {
    "title": "string",
    "frontText": "string",
    "backText": "string",
    "source": "reflection | conversation | manual"
  }
}
```

执行规则：

- `title` 和 `frontText` 必填。
- `backText` 可选，但推荐生成。
- 本地执行后写入 `lumostime_principles`。
- 写入后触发 `principleLibraryChanged` 和本地数据更新时间。
- 应用结果卡支持撤销，撤销时删除该原则。

## 理论引用策略

“理论引用放在 AI 行为层”指的是：不先做一个静态心理学理论库页面，也不把理论资料作为原则卡保存。原则库仍然保存用户自己的原则；心理学理论只作为 AI 在解释和运用原则时的表达框架。

第一版可在前台工具提示词中加入轻量行为规则：

- 成长型思维：避免把一次失败解释为人格失败。
- 自我效能感：强调可完成的小行动会恢复能动性。
- 认知解离：帮助用户把想法当作想法，而不是事实。
- 自我同情：鼓励时不羞辱用户，也不把痛苦包装成鸡汤。
- 执行意图：把抽象愿望落到“如果 X 发生，我就做 Y”。
- 价值澄清：把行动连接到用户想成为什么样的人。

这些理论不会作为静态数据参与检索。AI 只有在调用原则并组织回复时使用它们。

## 数据与执行流

### 调用原则

1. 用户发起普通对话。
2. AI 判断当前问题是否需要原则支持。
3. 需要时返回 `localQueryRequest`，target 包含 `principles`。
4. 本地查询原则库并回灌结果。
5. AI 基于原则、对话上下文和轻量理论框架生成回复。

### 添加原则

1. 用户进行复盘或总结。
2. AI 判断是否已经形成稳定、可复用的原则。
3. AI 返回 `create_principle` toolCall。
4. 本地写入原则库。
5. 聊天显示已添加卡片和撤销按钮。
6. 用户撤销时删除对应原则。

## 错误与边界

- 如果原则库为空，查询结果明确返回 no hits，AI 可以先基于通用框架回应，但不要假称引用了用户原则。
- 如果 AI 生成的新原则标题或正面文字为空，本地拒绝写入并显示失败卡片。
- 如果生成内容明显重复已有原则，AI 应优先引用已有原则；本地第一版可不做强去重，后续再加相似度提示。
- 背景模式暂不自动创建原则，避免用户不知情时写入个人原则库。

## 测试策略

- `assistantLocalSearchService`：覆盖 `principles` target 查询、空原则库、关键词命中、完整列表回灌。
- `aiService`：覆盖 `create_principle` toolCall normalization，空字段丢弃或拒绝。
- `assistantActionExecutor` 或新原则执行服务：覆盖创建原则、撤销删除、事件触发、本地时间戳更新。
- `AIBackfillChatForegroundTurn`：覆盖原则查询回灌循环，以及带原则 toolCall 的应用结果。
- `PrincipleLibraryView`：覆盖卡片详情入口和编辑保存。

## 第一阶段交付范围

第一阶段只做以下内容：

- 普通对话可按需查询原则库。
- 普通对话可直接创建原则并支持撤销。
- 原则库卡片可进入详情修改。
- 前台 AI prompt 增加原则调用和原则生成规则。

暂不做：

- 独立原则模板对话。
- 静态心理学理论库页面。
- 原则相似度合并。
- 背景模式自动写入原则。
