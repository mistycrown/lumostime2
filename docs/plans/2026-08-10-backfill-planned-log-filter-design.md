# 补记时间排除计划块设计

## 目标

所有“添加补记”入口在推断时间范围时只使用实际记录，不把时间轴计划块当作已经发生的记录。

## 方案

- 将可参与补记时间推断的记录定义为 `isPlanned !== true`。
- `App.tsx` 计算传入弹窗的最近记录结束时间时排除计划块，修复新建补记的默认开始时间与清除草稿后的重置时间。
- `useLogManager.openAddModal` 在右下角入口预填时间前排除计划块，避免计划块在进入表单前污染时间范围。
- `useLogForm` 计算“到上尾”的上一条记录时排除计划块，保证所有复用该弹窗的入口遵循同一规则。
- 快速打点也只使用实际记录作为起点，避免相邻的快速补记路径复用同一错误。
- “到现在”继续以当前时间为结束时间；其开始时间由已修复的默认推断决定。

## 边界

- 未标记 `isPlanned` 的旧记录仍视为实际记录，保持兼容。
- 没有实际记录时保留既有回退：默认开始于一小时前，“到上尾”继续使用既有的回退逻辑。
- 不改变计划块的保存、展示或统计以外的行为。

## 验证

- 单测覆盖默认最近结束时间和“到上尾”忽略计划块、保留普通记录，以及无实际记录的回退。
- 运行相关 Vitest 测试和 `npm run build`。
