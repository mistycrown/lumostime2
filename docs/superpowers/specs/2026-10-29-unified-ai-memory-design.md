# AI 统一记忆改造需求

_2026-10-29 · 本轮对话确认的需求，供执行计划引用_

## 🎯 要解决的问题

把长期记忆与 Dream 内容合成一个记忆库，提醒单独管理。记忆可以持续增加，但每次聊天只读取必要部分。Dream 负责定期整理同一个记忆库，能够新增、修改和删除内容。

## 📋 页面与操作

- AI 设置新增“记忆”tab，与“人设设置”“调用设置”并列。
- 默认文件夹名称固定为“关于我”“正在做的事”“过往经历”“发现的规律”。允许新增自定义文件夹、重命名和移动条目。
- 文件夹内可以新建、编辑、删除记忆；重要条目可以设置“始终记住”。
- 移除原来的“查看长期记忆”“打开 Dream”两个独立入口；`dream` 命令保留为新版整理入口。
- 提醒的列表、编辑、删除和定时规则有独立管理入口，不出现在记忆页。记忆开关、清空记忆不影响提醒。
- 视觉沿用现有主题、字体和下划线 tab，文件夹以图标、名称、数量组织；详情使用文字列表，减少嵌套容器。支持深浅主题、窄屏、Android 返回键和键盘遮挡。
- 自动整理设置、立即整理、整理记录放在记忆 tab；设置使用简短标签，不增加按钮下解释文案。

## 📚 旧内容怎样处理

| 原内容 | 处理 |
| --- | --- |
| 用户画像、偏好 | 默认迁入“关于我”，保留原文和旧版来源 |
| 工作记忆摘要 | 迁入“正在做的事”，标明旧摘要，不伪造最近进展 |
| Dream 条目 | 保留原文、原主题和时间范围，初始归入“发现的规律”；可按明确规则/后续整理移动到其他文件夹 |
| 用户当前状态 | 旧状态不重新当作当前状态；新状态在独立短期状态中使用并自动过期 |
| Agent 近期决策 | 不整体迁入记忆库；后续决策记录仅进入调用历史 |
| 活跃提醒 | 以独立提醒队列为准；队列键不存在时才恢复旧记忆里仍有效的待触发提醒 |
| 自定义 Dream 主题 | 保留为“整理关注主题”，不冒充记忆文件夹 |

迁移前保存一次原始旧数据，重复启动、恢复旧备份不重复导入。原始快照只用于备份和恢复，不进入模型请求。手动删除的记忆不得被旧数据迁移、Dream、聊天重试或同步重新恢复。

## 📥 如何读取记忆

- 关于我：少量重要内容常驻，其他细节按需读取；长期保存不等于全量注入。
- 正在做的事：按当前话题和最近实际进展选择。Dream 改写文字不刷新“最近进展”。
- 过往经历、发现的规律：关键词、实体、日期与可选向量检索组合；没有相关内容可以不带。
- 提供统一的搜索和条目/来源展开能力。近期对话只出现一次，摘要只覆盖更早的历史。
- 设置统一的请求长度预算，记录各部分估算用量及 provider 实际 usage；不能声称估算值是精确 token 数。
- 没有配置向量模型或请求失败时，仍可使用本地关键词检索，不能影响正常聊天。

## 🔄 对话与提醒分开

前台聊天、后台助理和定时来信都使用同一套新增、修改、删除、移动记忆操作。提醒有独立的创建、修改、取消操作、输入上下文和结果展示。同一轮允许同时执行两种操作，但一种操作失败、关闭或清空不能连带改变另一种。

用户明确表达和 AI 推断分开标记。手动维护的条目优先，自动整理不擅自修改或删除它们；可以提出候选建议。AI 生成条目允许自动整理新增、改写、移动及软删除，并保留实际变更记录和恢复能力。

## ⏰ 新版 Dream

- 从上次成功处理的位置读取新增/修改的聊天、日志、待办与复盘，并找相关旧记忆比较。
- 不再要求选择一个月。按天分批处理，材料多时跨批继续，不能只保留月初的前 200 条。
- 合并重复、修正旧理解、整理进行中的事、归纳有依据的规律；材料不足时允许不新增。
- 每个修改、删除必须指向确切条目和读取时版本；检查来源是否仍存在，防止覆盖用户刚刚做的修改。
- 手动和自动入口使用同一个整理函数。展示记录从实际成功的操作生成，不能反向合成记忆；整理记录不作为新的现实证据。
- 自动开关和频率可配置；有新材料才调用模型。无网络、配置不完整或失败时保留进度，下次合理重试。
- 第一版自动运行范围：应用进程运行且数据已加载时定时检查，应用恢复/重新打开时补跑；必须不依赖 AI 弹窗当前可见。应用被系统完全终止时不承诺准点执行。独立 Android 原生 Dream 执行器不在本轮范围。

## ✅ 完成标准

旧数据可迁移、可备份恢复；超过 24 条仍完整保存；一个记忆入口完成管理；提醒独立；聊天可修改和删除指定记忆；普通请求不全量携带记忆；配置向量模型后语义召回有效，未配置时正常工作；Dream 手动和自动整理均支持受约束的增删改；删除不会被重试、同步和后续整理复活。

执行约束以仓库 AGENTS.md 为准：UTF-8，native 顺序执行，不开 subagent，不在工作区编译 Android。只有计划/设计文档时不自动提交 Git；代码阶段完成验证后再按逻辑修改提交。
