# 沉浸式计时显示内容与格式切换设计
日期：2026-04-06

## 背景

当前沉浸式计时已经收敛为固定黑底白字样式，并完成了安卓全屏适配。接下来需要补上两类可切换能力：

1. 显示内容可以在“计时时间”和“当前时间”之间切换。
2. 显示格式可以在“时分”“分秒”“时分秒”之间切换。

同时，现有横屏布局里冒号占位过宽，挤压了数字字号；当分钟超过两位数时，数字槽位也需要自适应，避免 100 分钟以上出现截断或明显抖动。

## 目标

- 用户可以在沉浸式页面中快速切换“计时 / 当前”两种显示来源。
- 用户可以在“时分 / 分秒 / 时分秒”三种格式之间切换。
- `分秒` 模式下，分钟不封顶，显示 `70:25`、`128:08` 这类累计分钟。
- 横屏时进一步缩小冒号占位，把更多空间让给数字。
- 当某一段出现三位数时，槽位自动增宽，避免内容被压坏。

## 非目标

- 不改动沉浸式黑白主题本身。
- 不改动安卓全屏保护层方案。
- 不为这次功能引入新的主题、动画或额外弹窗流程。

## 方案选择

### 方案 A：两个独立按钮

- 一个按钮切换显示来源：`计时` / `当前`
- 一个按钮切换显示格式：`时分` / `分秒` / `时分秒`

优点：

- 语义最清楚，用户容易理解当前状态
- 代码职责明确，便于测试
- 后续如果还要记忆上次选择，也容易扩展

缺点：

- 顶部会比现在多一个按钮

### 方案 B：单按钮轮换所有组合

优点：

- 按钮数量少

缺点：

- 6 种组合串在一起，用户不容易预判下一次切换会到哪一档
- 测试和维护都更绕

最终采用方案 A。

## 交互设计

顶部控制区从当前的 3 个按钮扩展为 5 个按钮：

- 返回
- 提交
- 显示格式
- 显示内容
- 白噪声

其中右侧三个按钮并排放置：

- 显示格式按钮：循环切换 `时分` -> `分秒` -> `时分秒`
- 显示内容按钮：切换 `计时` <-> `当前`
- 白噪声按钮：保持现有行为

按钮视觉继续沿用当前沉浸式黑白控制面样式，不新增颜色体系。

## 数据与渲染模型

在 `ImmersiveTimer` 中新增两个局部状态：

```ts
type ImmersiveDisplaySource = 'elapsed' | 'current';
type ImmersiveDisplayFormat = 'hoursMinutes' | 'minutesSeconds' | 'hoursMinutesSeconds';
```

渲染流程拆成两步：

1. 先根据 `displaySource` 解析基础时间值
2. 再根据 `displayFormat` 生成最终要显示的段

### 计时时间

- `时分`：显示累计小时与当前小时内分钟，如 `01:23`
- `分秒`：显示累计分钟与秒，如 `83:05`
- `时分秒`：显示 `01:23:05`

### 当前时间

- `时分`：显示当前本地时间小时与分钟，如 `13:30`
- `分秒`：显示当前本地时间分钟与秒，如 `30:18`
- `时分秒`：显示当前本地时间 `13:30:18`

## 自适应规则

### 横屏冒号

当前横屏冒号占位继续缩小，不再与数字接近同等视觉宽度。目标是数字尽可能大，冒号只保留必要的辨识度。

### 数字槽位

数字槽位不再固定写死为单一宽度，而是根据当前显示段里最长数字长度计算：

- 两位数字时保持当前稳定宽度
- 三位及以上时按位数放宽
- 冒号槽位保持更窄的单独宽度

这样可以兼顾：

- `09:58` 这类普通情况稳定不跳
- `128:08` 这类三位分钟不挤压

## 测试策略

### 纯逻辑测试

新增纯函数测试，覆盖：

- `elapsed + hoursMinutes`
- `elapsed + minutesSeconds`
- `elapsed + hoursMinutesSeconds`
- `current + hoursMinutes`
- `current + minutesSeconds`
- `current + hoursMinutesSeconds`
- 三位分钟场景的最长数字位数计算

### 配置测试

更新沉浸式配置测试，覆盖：

- 控件列表包含新增的显示来源与显示格式按钮
- 横屏冒号宽度配置比当前更紧凑

## 风险

- 当前时间测试如果直接依赖系统时间会不稳定，因此需要把 `Date` 输入显式传入纯函数。
- 如果把显示逻辑全部堆回组件里，后续按钮增多时会继续膨胀，因此本次优先抽出纯逻辑函数。

## 结论

本次改动保持沉浸式计时现有黑白基调不变，只补充两个高频切换维度：显示来源与显示格式。核心实现重点不是新样式，而是把显示逻辑抽离为可测试的纯函数，同时让横屏布局把空间优先让给数字。
