# 沉浸式计时数字透图与画面样式选择设计
日期：2026-04-06

## 背景

当前沉浸式计时已经具备：

- 黑底白字的全屏沉浸式展示
- 横竖屏布局切换
- 显示内容与格式切换
- 白噪音选择弹窗

本次需求是在这个基础上，把沉浸式计时的数字区域升级为“静止数字遮罩 + 动态画层透出”的视觉形式，并新增一个视觉配置入口：

1. 黑色区域继续作为纯遮罩背景
2. 预置画作来自 `public/timer_bak`
3. 画面只在数字内部可见，数字外部不透图
4. 数字本身不能跟着动画移动、旋转或缩放
5. 横屏和竖屏都要支持该效果
6. 白噪音按钮旁边新增一个视觉按钮
7. 视觉按钮打开一个弹窗，上半部分选画作，下半部分选运动样式

用户进一步确认了两个关键约束：

- 三种运动方向都保留，做成样式选择器，而不是只实现其中一种
- 由于需要同时选择“画作”和“运动样式”，不能用单击直接轮播，必须改为弹窗选择

## 目标

- 让沉浸式计时获得更强的视觉沉浸感，但不破坏读时效率
- 保持数字位置稳定，让用户始终把它感知为计时数字而不是动画对象
- 支持从预置画作中切换当前渲染图片
- 支持在三种动画样式之间切换
- 让画作和动画样式都能记住上次选择，下次进入沉浸式计时时自动恢复

## 非目标

- 不支持用户上传自定义图片
- 不改动白噪音的已有弹窗和声音逻辑
- 不新增第四种以上动画样式
- 不把画作显示到数字外部背景
- 不做实时强交互编辑器，例如动画速度滑杆、旋转角度滑杆、透明度滑杆

## 方案选择

### 方案 A：视觉按钮打开单按钮双分区弹窗

- 沉浸式右上角新增一个“画面”按钮
- 点击后打开一个独立弹窗
- 上半部分显示画作列表
- 下半部分显示运动样式列表

优点：

- 最符合用户明确指定的交互形式
- 画作与样式职责清晰，理解成本最低
- 后续扩展更多画作时仍然稳定

缺点：

- 比“单击切下一张图”多一步操作

### 方案 B：复用白噪音弹窗，合并为多分区弹窗

优点：

- 按钮数量少

缺点：

- 听觉和视觉配置混在一起，打断感更强
- 现有白噪音逻辑与视觉逻辑耦合，维护更差

### 方案 C：单按钮直接轮播图片，长按切换样式

优点：

- 表面上最省空间

缺点：

- 与用户最终确认的交互不符
- 手势语义不清晰，记忆成本高

最终采用方案 A。

## 视觉设计

### 1. 基本结构

沉浸式主视图拆成三层：

1. 最底层：纯黑背景层
2. 中间层：动态画层
3. 最上层：静止数字遮罩层

其中真正可见的效果不是“数字文字本身填充背景图”，而是“数字形状作为可视窗口，让中间层画面只在数字内部露出”。数字外部区域继续被黑色背景完全覆盖。

### 2. 数字行为

- 数字位置固定
- 数字字形固定
- 数字不参与平移
- 数字不参与旋转
- 数字不参与缩放

也就是说，动的是“数字背后的画层”，不是数字本体。

### 3. 横竖屏表现

- 竖屏继续沿用当前纵向堆叠的大数字结构
- 横屏继续沿用当前横向一行时间结构
- 两种布局都复用同一个动态画层和遮罩机制

布局差异只体现在数字排版，不体现在动画模型。

### 4. 画作来源

首批画作固定取自 `public/timer_bak`，当前目录下已有这些资源：

- `640x0.jpg`
- `Monet_-_Impression,_Sunrise.jpg`
- `Moreno_Garden_Bordighera_1884_-_The_Norton_Museum_Miami_Florida.jpg`
- `Three_Cows_Grazing_by_Claude_Monet.jpg`
- `Van_Gogh_-_Starry_Night_-_Google_Art_Project.jpg.webp`
- `Vincent_Willem_van_Gogh_127.jpg`

实现中不直接写死零散字符串到 JSX，而是抽成统一配置数组，保证按钮、弹窗、持久化、默认值都共用同一份数据源。

## 动画样式设计

保留三个样式，并做成可切换预设：

### 1. 扫掠

- 画层做明显的横向或斜向平移
- 带轻到中等幅度的旋转
- 节奏相对顺滑，第一眼动态感明确

这是默认推荐样式，因为兼顾可感知运动和读时稳定性。

### 2. 轨道旋转

- 画层做更明显的绕中心轨迹运动
- 旋转幅度大于“扫掠”
- 视觉存在感最强

适合更戏剧化的沉浸感，但也最容易喧宾夺主。

### 3. 分层漂移

- 画层做较慢的位移
- 配合较轻旋转
- 节奏更平稳，耐看度更高

适合长时间使用场景。

### 动画边界

- 三种样式都只作用于画层
- 动画通过 CSS transforms 或等价方式实现
- 不引入高成本的逐帧 canvas 动画
- 不要求根据画作内容动态分析运动路径

## 交互设计

### 顶部控制区

当前右上角已有：

- 显示格式
- 显示内容
- 横竖屏切换
- 白噪音

本次新增：

- 画面按钮

放置位置：

- 紧挨白噪音按钮
- 与现有圆形控制按钮保持同一视觉规格

### 画面弹窗

新增独立弹窗，不复用白噪音弹窗标题与数据源，但可以复用现有沉浸式弹窗视觉主题。

结构：

- 标题：`画面样式`
- 第一分区：`选择画作`
- 第二分区：`选择运动样式`

第一分区展示方式：

- 缩略图网格
- 当前选中项高亮
- 点击后立即更新预览

第二分区展示方式：

- 三个样式选项卡或列表卡片
- 标题分别为 `扫掠`、`轨道旋转`、`分层漂移`
- 可附一行短描述，帮助区分动态强弱

交互规则：

- 点击画作立即切换当前画层
- 点击样式立即切换当前运动样式
- 不需要额外“确认”按钮
- 关闭弹窗后保留当前选中结果

## 数据模型

建议新增两类显式类型：

```ts
type ImmersiveArtId =
  | '640x0'
  | 'impression-sunrise'
  | 'moreno-garden'
  | 'three-cows'
  | 'starry-night'
  | 'van-gogh-127';

type ImmersiveMotionStyle = 'sweep' | 'orbit' | 'drift';
```

建议新增统一配置：

```ts
interface ImmersiveArtOption {
  id: ImmersiveArtId;
  name: string;
  src: string;
  thumbnailSrc?: string;
}

interface ImmersiveMotionOption {
  id: ImmersiveMotionStyle;
  name: string;
  description: string;
}
```

本次配置应放在沉浸式相关配置文件或独立工具文件中，避免 `ImmersiveTimer` 组件继续膨胀。

## 持久化策略

新增两个本地存储键：

- `immersiveTimerArt`
- `immersiveTimerMotionStyle`

规则：

- 进入沉浸式计时时先读取本地存储
- 如果读到非法值，回退到默认值
- 用户在弹窗中切换后立即写回本地存储

建议默认值：

- 默认画作：`starry-night`
- 默认运动样式：`sweep`

## 渲染实现建议

### 1. 遮罩实现

优先使用浏览器原生遮罩能力实现数字透图，例如：

- `mask-image` / `-webkit-mask-image`
- 或等价的 SVG mask / clipPath 方案

实现原则是：数字只是遮罩，画层才是真正有颜色和动画的内容。

不建议继续沿用“文字 background-clip”假装遮罩的方式，因为它容易让文字本身参与背景定位，概念上不够清晰，也更难保证“数字完全静止、只有画层在动”。

### 2. 横屏与竖屏复用

建议把“时间文本结构”和“遮罩渲染结构”拆开：

- 一层负责根据 `displayParts` 和方向生成静态数字布局
- 一层负责承载动态画层并应用遮罩

这样横竖屏都可以复用同一套视觉机制，只替换布局骨架。

### 3. 弹窗复用策略

当前已有 `ImmersiveSelectorModal` 仅适合简单单列表选择。由于本次需要上下双分区，不建议硬塞进原组件。

更推荐：

- 新建一个轻量的 `ImmersiveVisualSelectorModal`
- 继续复用现有沉浸式 modal theme 常量

这样职责更清晰，也不会把白噪音选择器做坏。

## 测试策略

### 单元测试

新增或补充纯逻辑测试，至少覆盖：

- 画作默认值回退
- 动画样式默认值回退
- 非法本地存储值归一化
- 画作配置和样式配置可被正确枚举

### 组件级手工验证

至少验证以下场景：

1. 竖屏下数字静止，图片只在数字内部可见
2. 横屏下数字静止，图片只在数字内部可见
3. 三种动画样式切换后都能看到明显差异
4. 切换画作后即时生效
5. 退出沉浸式再进入，仍能恢复上次选择
6. 白噪音弹窗行为不受影响
7. 显示格式、显示内容、横竖屏切换与新视觉层可同时工作

### 构建验证

- 运行相关测试
- 运行 `npm run build`

## 风险

- CSS 遮罩在部分 WebView 环境中的兼容性可能不如普通文本渲染稳定，需要优先确认当前 Electron 与移动端 WebView 是否都能正常显示
- 如果直接把所有新逻辑堆进 `ImmersiveTimer.tsx`，该文件会继续膨胀，因此必须把配置、持久化和弹窗拆出去
- 画作资源尺寸和比例不一致，缩略图网格需要容忍裁切，主画层则要统一采用 cover 策略

## 结论

本次改动的核心不是“给数字加一层图片纹理”，而是把沉浸式计时重构为“纯黑背景 + 动态画层 + 静止数字遮罩”的视觉系统。交互上通过新增独立“画面”按钮和双分区弹窗，让用户分别选择画作与运动样式；实现上通过配置化画作、样式预设和本地持久化，把这套视觉能力控制在可维护范围内。
