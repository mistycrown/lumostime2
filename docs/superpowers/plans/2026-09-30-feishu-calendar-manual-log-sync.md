# 飞书日历手动同步 Log 实施计划

**目标：** 用户连接飞书后，点击“同步到飞书日历”才上传尚未同步的实际 Log；重复点击不会产生重复日程。

**执行方式：** Native，按任务顺序实现和验证。本文件仅是计划，不启动开发。

**依据：** 当前 `Log` 有稳定 `id`、起止时间、标题和备注；数据由 `DataContext` / `dataRepository` 持久化，设置页已有“数据与同步”分组。飞书提供[创建日程 API](https://open.feishu.cn/document/server-docs/calendar-v4/calendar-event/create)和[获取主日历 API](https://open.feishu.cn/document/server-docs/calendar-v4/calendar/primary)。

**拟新增的文件边界：** `src/views/settings/FeishuCalendarSettingsView.tsx` 负责交互；`src/services/feishuCalendarClient.ts` 负责应用端请求；`src/utils/feishuLogEvent.ts` 负责筛选与字段转换；`api/feishu/` 负责 OAuth、日历查询与同步接口；`api/feishu/syncLedger.ts` 负责唯一键、状态与远端核查。现有 `src/views/SettingsView.tsx` 只接入设置入口。测试靠近各自模块。

## 范围与用户行为

- 在“设置 → 数据与同步”新增独立的“飞书日历”页面：连接账号、显示目标日历、预览待同步数量、点击同步、查看结果、断开连接。
- 只在按钮点击后执行；应用启动、Log 增删改、现有 WebDAV/S3 同步均不触发飞书请求。
- 首次默认扫描全部历史实际 Log。排除 `isPlanned`、无效时间段和演示/回退数据；不上传图片、评论、情绪及其他私密字段。日程标题取 Log 标题或活动名，说明取备注，时间取 Log 起止时间；创建为“空闲”且不设置提醒。
- 同一飞书账号、同一目标日历、同一 Log ID 只创建一次。已同步 Log 即使之后在应用内被修改，第一版仍跳过；在应用内删除 Log 也不删除飞书日程。换目标日历时视为新的同步目标。
- 同步前显示“待新增 / 已同步 / 不符合条件”数量；结束后显示“新增 / 跳过 / 失败”数量。失败项下次可重试；未知结果项先核查，不能直接再次创建。

## 技术设计与查重

1. **授权与凭证。** 创建飞书开放平台应用，申请日历写入所需权限，采用用户授权访问其可写日历。新增小型服务端承接授权回调、刷新凭证和调用飞书 API；App Secret 与刷新凭证不写入前端包、日志或普通备份。Web、Electron、Android 均通过同一连接流程完成授权返回。实施前在飞书测试租户核实具体权限、回调地址、令牌刷新和日历类型限制。
2. **目标日历。** 第一版连接后默认用户主日历；页面显示账号和日历名称，允许选择另一个有写入权限的日历。同步键使用飞书租户/用户 ID、`calendar_id`、`log.id`，避免不同账号或日历互相误判。
3. **服务端同步账本。** 保存上述同步键、飞书 `event_id`、创建状态和时间；同步键设唯一约束。同一键只允许一个进行中的创建操作。服务端账本用于跨设备、重装及本地备份恢复后的查重；前端只保留连接状态和展示所需的非敏感信息。
4. **飞书侧核查。** 每个创建的日程说明附一个明确的 LumosTime 来源标记与 Log ID。执行创建前，对无账本记录或上次结果不明的 Log，按相关时间范围列举目标日历日程并检查标记；找到后补写 `event_id` 并跳过创建。查询失败时停止该范围的创建，避免因无法查重而重复上传。现存且没有该标记的手工日程不能仅凭标题/时间认定为已同步。
5. **批次与失败恢复。** 前端一次点击提交待同步 Log；服务端限速分批处理、逐条记账。创建返回成功后立即保存 `event_id`；超时或进程中断后先查飞书侧标记再重试。客户端重复点击由按钮锁和服务端唯一约束共同阻止。授权过期、权限不足、日历不可写、限流和网络失败分别反馈，保留已完成进度。

## 实施任务

### 1. 授权及最小服务端

- 新增服务端入口、环境变量校验、授权发起/回调、令牌安全存储和刷新；配置飞书应用的回调地址与日历权限。
- 验证：测试账号完成连接；过期令牌可以刷新；错误 `state`、撤销授权和缺少权限均不会创建日程；构建产物及备份中没有 App Secret。

### 2. 日历连接与设置页

- 在 `src/views/SettingsView.tsx` 的“数据与同步”分组增加入口；新增聚焦的飞书日历设置子页及连接状态服务，不混入 WebDAV/S3 页面。
- 验证：未连接、连接中、已连接、断开及无写入权限状态显示正确；未点击同步时没有创建日程请求。

### 3. Log 转换与候选筛选

- 新增纯函数，将实际 Log 转为飞书日程请求；按 `isPlanned`、时间有效性和数据就绪状态过滤。时间戳从毫秒换算为秒，保留用户所在时区。
- 验证：标题回退、备注、跨时区时间、计划 Log、无效时间和重复 Log ID 的单元测试通过。

### 4. 同步账本与远端查重

- 新增持久化账本及唯一约束；接入目标日历日程列表查询、分页与来源标记识别；实现“已成功 / 待创建 / 结果不明”的决策。
- 验证：第二次同步跳过全部已成功项；本地重装或导入原 Log 后仍跳过；创建成功但记账失败、请求超时、并发点击均不会再次创建；远端查询失败时不创建。

### 5. 手动批量同步与结果页

- 实现点击触发、同步前计数、分批上传、进度与结果汇总；只重试确认未创建的失败项。
- 验证：空列表、部分失败、限流、断网后重试均给出准确计数；同步后编辑或删除原 Log 不触发飞书更新/删除。

### 6. 集成验证与交付

- 用飞书测试日历分别在 Web、Electron、Android 做手动冒烟测试：首次上传、再次点击、跨设备点击、断网恢复、换日历、断开重连。执行相关单元测试和 `npm run build`；Android 只执行 `npx cap sync android`，不在仓库内编译 Android。
- 检查 Git diff，只提交本功能文件；记录所需飞书应用配置、服务端部署参数与用户可见的第一版限制。

## 交付判定

同一账号和目标日历中，第一次点击只新增合格且未同步的 Log；第二次点击新增 0 条。请求结果不明、跨设备重复点击或恢复备份后，系统先核查账本和飞书侧来源标记，不能盲目补建。整个过程由用户点击启动，并能看到准确结果。

## 前置条件与已知边界

- 需要可部署的 HTTPS 服务端与持久化数据库，以及飞书开放平台应用。仓库目前没有现成服务端；这是实现安全授权和跨设备查重的新增基础设施。
- 该版本是**仅新增的单向同步**。已同步记录的后续修改、删除及飞书侧修改不做双向对账。
- 即使用户在飞书侧手动删除了已同步日程，账本仍认定该 Log 已同步；第一版不会重新创建。
- 对接入前已存在、没有 LumosTime 来源标记的飞书日程，无法可靠判定是否与某条 Log 相同，不使用标题/时间猜测匹配。
