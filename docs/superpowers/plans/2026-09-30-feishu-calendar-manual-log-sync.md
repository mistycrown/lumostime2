# 飞书日历手动同步 Log 实施计划

**目标：** 用户连接飞书后，点击“同步到飞书日历”才上传尚未同步的实际 Log；重复点击不会产生重复日程。

**执行方式：** Native，按用户当前要求分阶段实现和验证。

**依据：** 当前 `Log` 有稳定 `id`、起止时间、标题和备注；数据由 `DataContext` / `dataRepository` 持久化，设置页已有“数据与同步”分组。飞书提供[创建日程 API](https://open.feishu.cn/document/server-docs/calendar-v4/calendar-event/create)和[获取主日历 API](https://open.feishu.cn/document/server-docs/calendar-v4/calendar/primary)。

**文件边界：** `src/views/settings/FeishuCalendarSettingsView.tsx` 负责交互；`src/services/feishuCalendarClient.ts` 负责应用端请求；`server/feishu/` 负责 OAuth、持久化连接、HTTP 路由和导入；`electron/feishuConnection.ts` 负责桌面会话桥接。`src/utils/feishuLogImport.ts` 负责 Log 筛选与转换，`server/feishu/calendarImport.ts` 与 `oauthStore.ts` 负责分类日历映射、正式导入账本与远端核查。现有 `src/views/SettingsView.tsx` 只接入设置入口。测试靠近各自模块。

## 2026-10-02 实施进展

已实现统一服务 OAuth 发起/回调、单次 state 与 PKCE、每用户加密持久化授权、刷新令牌、连接状态、可写日历选择、断开连接，以及用户授权后手动导入 15 分钟测试日程。服务端及 HTTP 路由位于 `server/feishu/`，由独立 Node 服务承接。Web 使用 HttpOnly 会话 Cookie，Electron 通过主进程会话请求，Android 通过原生 HTTP；外部浏览器回调更新原应用会话，应用仅在等待授权时轮询连接状态。配置说明见 [飞书日历授权说明](../../feishu-calendar-test.md)。

后续增量已实现正式 Log 分批导入、加密持久化账本、远端查重及按活动分类自动创建/复用日历。连接按钮始终显示；日期为八位数字输入。测试块失败重试使用同一飞书幂等键。自动化验证使用模拟飞书响应；真实账号和各平台页面冒烟测试仍需实际飞书应用凭证、回调域名与可用浏览器。没有配置时，界面显示连接服务尚未开通。

维护者已确认尚未创建飞书应用、尚未部署连接服务，因此功能尚不能真实绑定。开发命令已接入本地 API 自动启动，桌面开发版使用同一个本地服务；异常 HTML/空响应不再笼统显示网络错误。OAuth 显式请求确认并采用 v3 令牌接口。对外跨企业提供统一授权，还需商店应用资格、上架审核和租户管理员开通，不能把自建应用测试视为公共服务发布完成。

## 范围与用户行为

- 在“设置 → 数据与同步”新增独立的“飞书日历”页面：连接账号、显示目标日历、预览待同步数量、点击同步、查看结果、断开连接。
- 只在按钮点击后执行；应用启动、Log 增删改、现有 WebDAV/S3 同步均不触发飞书请求。
- 正式同步前提供八位数字开始/结束日期（`YYYYMMDD`），默认本周；支持“本周、本月、上周、上月”快捷填充后继续输入修改。周范围为周一至周日，月范围为完整自然月；按设备本地日期解释，开始日期从 00:00 起，结束日期包含当天全天。无效或倒置日期不允许导入。
- 扫描所选范围内开始的实际 Log（`startTime >= 开始日期 00:00` 且 `startTime < 结束日期次日 00:00`）；跨午夜记录保留完整原始起止时间。排除 `isPlanned`、无效时间段和演示/回退数据；不上传图片、评论、情绪及其他私密字段。日程标题取 Log 标题或活动名，说明取备注，时间取 Log 起止时间；创建为“空闲”且不设置提醒。
- 同一飞书账号、同一目标日历、同一 Log ID 只创建一次。已同步 Log 即使之后在应用内被修改，第一版仍跳过；在应用内删除 Log 也不删除飞书日程。换目标日历时视为新的同步目标。
- 导入前显示范围内合格记录/分类数量和分类日历对应关系；已导入判断在服务端实际处理时完成，结束后显示“新增 / 跳过 / 失败”数量。明确被飞书拒绝的失败项可重试；未知结果项先核查，不能直接再次创建。

## 技术设计与查重

**2026-10-02 已确认的配置方式：** 采用 LumosTime 统一连接服务。普通用户只通过“连接飞书”发起授权，不填写服务地址、测试口令、App ID/App Secret，也不自行部署服务或获取访问令牌。统一服务地址由维护者配置到客户端；服务端凭证、授权回调和持久化存储由维护者配置。固定测试令牌和口令入口已移除，所有测试均使用当前用户独立授权。应用类型与发布范围需覆盖实际用户，先在测试账号完成验证，再按目标使用范围发布。

1. **授权与凭证。** 创建飞书开放平台应用，申请日历写入所需权限，采用用户授权访问其可写日历。新增小型服务端承接授权回调、刷新凭证和调用飞书 API；App Secret 与刷新凭证不写入前端包、日志或普通备份。Web、Electron、Android 均通过同一连接流程完成授权返回。实施前在飞书测试租户核实具体权限、回调地址、令牌刷新和日历类型限制。
2. **目标日历。** 按用户后续要求，每个活动分类自动对应一个私密日历，首次使用分类颜色并订阅；按账号和稳定分类 ID 复用，仅为实际导入或测试需要的分类创建，不按标签创建。日程跟随日历颜色。同步键使用飞书账号 ID、`calendar_id`、`log.id`，避免不同账号或日历互相误判。
3. **服务端同步账本。** 保存上述同步键、飞书 `event_id`、创建状态和时间；同步键设唯一约束。同一键只允许一个进行中的创建操作。服务端账本用于跨设备、重装及本地备份恢复后的查重；前端只保留连接状态和展示所需的非敏感信息。
4. **飞书侧核查。** 每个创建的日程说明附一个明确的 LumosTime 来源标记与 Log ID。执行创建前，对无账本记录或上次结果不明的 Log，按相关时间范围列举目标日历日程并检查标记；找到后补写 `event_id` 并跳过创建。查询失败时停止该范围的创建，避免因无法查重而重复上传。现存且没有该标记的手工日程不能仅凭标题/时间认定为已同步。
5. **批次与失败恢复。** 前端点击后每批提交 5 条，服务端逐条处理、记账。创建返回成功后立即保存 `event_id`；超时或进程中断后先查飞书侧标记，仍未知时停止该记录，可能需维护者排查。客户端按钮锁、单实例服务端账号锁和持久化唯一键阻止重复操作。HTTP 429 停止当前批次，保留完成账本供后续导入核查；扩容需跨进程锁。

## 实施任务

### 1. 授权及最小服务端

- 新增服务端入口、环境变量校验、授权发起/回调、令牌安全存储和刷新；配置飞书应用的回调地址与日历权限。
- 验证：测试账号完成连接；过期令牌可以刷新；错误 `state`、撤销授权和缺少权限均不会创建日程；构建产物及备份中没有 App Secret。

### 2. 日历连接与设置页

- 在 `src/views/SettingsView.tsx` 的“数据与同步”分组增加入口；新增聚焦的飞书日历设置子页及连接状态服务，不混入 WebDAV/S3 页面。
- 页面已提供始终可见的“连接飞书”、授权后分类测试、八位数字日期范围、分类日历映射、正式导入及断开连接。用户点击连接后进入飞书授权，再返回应用。服务地址和技术凭证不作为普通用户表单项。
- 验证：未连接、连接中、已连接、断开及无写入权限状态显示正确；未点击同步时没有创建日程请求。

### 3. Log 转换与候选筛选

- 设置页已将所选日期转换为包含结束日期全天的时间边界，用于导入前计数、候选筛选及提交；切换范围时重新预览，不自动创建日程。

- 新增纯函数，将实际 Log 转为飞书日程请求；按 `isPlanned`、时间有效性和数据就绪状态过滤。时间戳从毫秒换算为秒，保留用户所在时区。
- 验证：标题回退、备注、跨时区时间、计划 Log、无效时间和重复 Log ID 的单元测试通过。

### 4. 同步账本与远端查重

- 新增持久化账本及唯一约束；接入目标日历日程列表查询、分页与来源标记识别；实现“已成功 / 待创建 / 结果不明”的决策。
- 验证：第二次同步跳过全部已成功项；本地重装或导入原 Log 后仍跳过；创建成功但记账失败、请求超时、并发点击均不会再次创建；远端查询失败时不创建。

### 5. 手动批量同步与结果页

- 实现点击触发、同步前计数、分批上传、进度与结果汇总；只重试确认未创建的失败项。
- 验证：空列表、部分失败、限流、断网后重试均给出准确计数；同步后编辑或删除原 Log 不触发飞书更新/删除。

### 6. 集成验证与交付

- 用飞书测试日历分别在 Web、Electron、Android 做手动冒烟测试：首次上传、再次点击、跨设备点击、断网恢复、换日历、断开重连。执行相关单元测试和 `npm run build`；Android 只执行 `npx cap sync android`，不在仓库内编译 Android。
- 检查 Git diff，只提交本功能文件；记录所需飞书应用配置、服务端部署参数与用户可见的第一版限制。

## 交付判定

同一账号和目标日历中，第一次点击只新增合格且未同步的 Log；第二次点击新增 0 条。请求结果不明、跨设备重复点击或恢复备份后，系统先核查账本和飞书侧来源标记，不能盲目补建。整个过程由用户点击启动，并能看到准确结果。

## 前置条件与已知边界

- 已有可部署的 OAuth 服务端、加密 SQLite 连接/账本、分类日历和跨设备查重代码；仍需维护者提供真实 HTTPS 域名、飞书应用配置和持久化单实例部署环境，完成真实账号及各平台页面验收。
- 该版本是**仅新增的单向同步**。已同步记录的后续修改、删除及飞书侧修改不做双向对账。
- 即使用户在飞书侧手动删除了已同步日程，账本仍认定该 Log 已同步；第一版不会重新创建。
- 对接入前已存在、没有 LumosTime 来源标记的飞书日程，无法可靠判定是否与某条 Log 相同，不使用标题/时间猜测匹配。
