# 飞书 Log 手动增量同步

**用户已确定的行为：** 点击同步时，新增创建、同分类修改更新、本地删除删除对应日程、分类变化删除旧日程后新建。继续使用日期范围、用户专属授权、Native 实施，不使用子代理。

**实现：** 在现有 import 接口增加账本清单和 sync 请求。以账号 + Log ID 建立独立索引并升级旧分类账本；客户端用完整且已加载的本地 Log 列表计算明确的删除 ID，不能从五条的小批次或日期筛选结果推断删除。所选范围包含旧同步时间时允许更新移出范围的记录。每次修改/删除先检查日程来源标记；迁移保存进度并先删后建，重试不重复创建。暂不做实时/双向同步，不扫描或删除无来源标记的用户日程。

- [x] 完整本地快照比对、删除专用批次、空范围可同步、操作计数、数据变化中止。
- [x] 更新、迁移、未知请求、删除、账号隔离、缺失标记、跨范围移动和旧账本回归。

**接口依据：** 飞书官方 CLI 日历目录中的 event.patch 与 event.delete；删除明确使用 `need_notification=false`。

**验证结果：** 121 项飞书测试通过（本次新增 13 项）；局部 TypeScript、Web/Electron 构建和 Android 资源同步通过，未编译 Android。服务独立 HTTP 启动及页面静态渲染回归通过。实际 UI 清单仍为 apps=[]、browsers=[]，无法完成页面手动冒烟和真实飞书删除/分类迁移验收，按仓库要求暂缓 Git 提交；本次代码保留在工作区，原有专属授权改动未混入提交。

**范围限制：** 删除和分类迁移依赖当前执行端保留的同步账本；更换独立设备、清空数据库或丢失账本后的全量远端重建不属于本次实现。
