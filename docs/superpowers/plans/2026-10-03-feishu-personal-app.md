# 飞书专属应用连接实施计划

**目标：** 按用户已确认的专属应用方案，点击连接打开飞书创建确认页，再授权用户日历。保留授权后的手动测试、分类日历、八位日期范围和导入查重。

**执行方式：** Native；采用已批准方案直接实施，不使用子代理。

**架构：** 使用飞书官方 CLI 的应用注册设备流程及用户设备授权流程，不需要公共 App ID/Secret，不需要 OAuth 网页回调。注册码、应用密钥和用户令牌由连接执行端加密保存，界面只接收官方确认 URL 和阶段状态。桌面端优先在主进程本机执行；Web/Android 使用连接服务，服务无需预先注册公共应用，但仍需部署地址与持久存储。不会宣称所有平台都免服务器。

- [x] 扩展加密连接数据、专属应用注册、设备授权、串行轮询、拒绝/过期/取消处理、用户权限和令牌刷新。
- [x] 服务默认采用专属应用模式；保留旧公共应用模式兼容验证。HTTP 和桌面桥接调用同一连接动作。
- [x] 桌面安全持久化本机凭证和账本；界面显示创建/授权阶段、打开授权页和继续按钮，不要求复制技术凭证。
- [ ] 运行模拟回归、无凭证真实注册入口检查、构建与 Android 资源同步。真实创建与导入仍需用户在飞书网页中确认。

**核实依据：** [官方注册实现](https://github.com/larksuite/cli/blob/main/internal/auth/app_registration.go)、[官方设备授权](https://github.com/larksuite/cli/blob/main/internal/auth/device_flow.go)。已实际确认注册 begin 不需要公共应用凭证且返回官方确认 URL；尚未确认用户账号和日历写入，不把入口可用当作导入成功。
