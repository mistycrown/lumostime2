# 同时计时偏好实现计划

**目标：** 偏好设置增加默认开启的“允许同时计时”；关闭后，从任何入口启动新活动都会保存并结束其他计时。

**架构：** React 的 SessionContext 统一执行应用、待办、Routine、桌面小组件及 NFC/深链接的切换；Android WidgetTimerController 统一执行普通、待办和场景小组件的后台切换。通过 WidgetBridge 同步偏好、已结束会话和运行状态，避免旧状态恢复已结束的计时。

**执行方式：** 按仓库要求由当前会话 native 执行，无需另行确认，不使用子代理。所有文件使用 UTF-8，不编译 Android。

- [x] 新增偏好开关及持久化、备份恢复，补设置显示检查。
- [x] 在 SessionContext 接入共享日志保存回调，切换时复用停止、跨日和图片保存流程；检查重复启动及连续切换。
- [x] Android 同步偏好并统一三个后台计时入口，保存停止记录并阻止旧状态回流；保留应用会话附加数据。
- [x] 运行相关回归、渲染冒烟和生产构建，执行 Capacitor 同步，检查本任务 diff 后提交。

**重点验证：** 默认兼容并行、关闭后单计时、重复同活动不重启、关闭开关不立即停止、跨来源切换、跨日记录、图片保存中的切换、过期同步不恢复旧会话。

**验证结果：** `vitest.timer.config.ts` 的 70 项测试通过；计时切换和原有计时图片两个 renderer 冒烟通过；移动浅色及桌面深色截图中文显示正常；`npm run build`、`npx cap sync android` 通过。全量 `tsc` 仍有其他未修改模块的既有错误，本次修改文件无类型报错。Android 按仓库约定未编译，NFC 与原生小组件仍需安装真机验证。
