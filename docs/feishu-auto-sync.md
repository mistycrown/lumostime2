# 飞书日历自动同步

入口：设置 → 数据与同步 → 飞书日历 → 自动同步。先连接账号并授权，再开启开关。

- 开启后的实际记录新增、修改、删除及分类迁移会自动同步。补记历史日期也会处理。
- 首次开启只建立基线，不批量导入已有历史记录。历史导入继续使用按日期范围的手动同步。
- 运行于应用前台，保存后约 2 秒开始，每批最多 5 条。离开设置页面不影响运行。
- 离线任务保存在本机；重新打开应用、返回前台或恢复网络后补同步。不开启 Android 后台服务。
- 开关和队列按账号、本机保存，不进入云同步和导出备份。建议只在一个主要设备开启自动同步。
- 关闭开关保留队列，再开启后继续处理暂停期间的变化；断开授权暂停写入，同账号重新授权后继续。
- 忽略分类沿用手动同步偏好，保护当前分类及原日历分类。取消忽略后继续处理原队列。
- 整体云下载、备份恢复、重置和清空数据暂停自动同步并重建基线，不据缺少记录批量删除飞书日程；需要重新开启。
- 飞书侧修改不回写 LumosTime。记录的图片不上传，单独修改图片不触发远端写入。

记录与待同步队列在同一 IndexedDB 事务中保存。localStorage fallback 使用可恢复写入日志，读取时先完成被中断的提交。删除记录保留 Log ID、原开始时间和分类信息；执行前核对账号同步清单。创建结果未知时，复用执行端账本和来源标记核查，不盲目再次创建。

成功只确认发送的任务版本，请求期间的再次编辑或删除仍留在队列。暂时失败按 5 秒、30 秒、2 分钟、最多 5 分钟退避；连续 8 次失败后暂停该条，用户可点“立即同步”重试。授权或明确权限/来源错误暂停任务，不影响其他有效记录。

验证命令：

```powershell
npm run feishu:test
node node_modules/vitest/vitest.mjs run src/repositories/storageRepository.test.ts src/repositories/dataRepository.test.ts
node scripts/check-feishu-auto-smoke.mjs
npm run build
npx cap sync android
```

页面冒烟运行隐藏、隔离的 Electron Chromium 和模拟 API，使用真实 React 设置页、DataProvider、IndexedDB 及全局调度。覆盖首次安装数据初始化与演示数据保护、开关、IndexedDB 批量写入失败整体回滚、离开设置后的新增、编辑、删除、离线落盘、刷新恢复和关闭/重开。没有使用真实账号写日历，真实飞书与 Android 实机验收仍需实际操作。
