# 待办详情「31 号无则月末」白屏排查复盘

## 问题现象

- 在待办详情的「细节」页中，只要点击“若当月没有 31 号，则自动定位到最后一天”，页面就会白屏。
- 控制台没有红色报错。
- 等待一段时间或刷新后，界面会回到时间线页。
- 同样的问题在勾选和取消勾选时都会发生。

## 最终有效修复

- 不再使用“隐藏原生 `checkbox` + 外层 `label`”这套交互。
- 改成纯 `button` 切换，并在 `onMouseDown` 阶段执行 `preventDefault()`。

## 经验教训

### 1. 没有报错，不等于不是交互控件本身的问题

这次最容易误判的地方，是我们先把问题当成了：

- recurrence 规则计算错误
- auto-save 死循环
- DataContext 回写抖动
- 时间线重算太重
- 页面卸载/重挂载异常

这些方向都“像”，但都不是最后真正命中的点。  
真正有效的修复，落在一个很小的 UI 原语上：`checkbox` 的默认行为链。

### 2. Electron / WebView 环境下，原生表单控件要格外保守

隐藏 `input[type="checkbox"]`、再用 `label` 包起来做自定义样式，在普通浏览器里常见，但在 Electron 或嵌套 WebView 环境中：

- 焦点切换
- `mousedown` / `click`
- `blur`
- 隐藏表单元素的默认激活行为

有时会走出非常难追的链路，而且不一定抛异常。  
这类场景里，优先考虑：

- 纯 `button`
- 显式 state toggle
- 在需要时阻断默认鼠标按下行为

### 3. “白屏但无错误”时，先怀疑同步 UI 事件链，再怀疑数据层

这次一开始花了太多时间在保存链、归一化、原生同步、后台视图上。  
更高效的顺序应该是：

1. 先把触发动作缩到最小：到底是“点控件就白”，还是“保存后才白”。
2. 如果是“点控件就白”，优先检查：
   - 原生表单元素
   - `label` 包裹点击
   - 焦点与 `blur`
   - 同步 `setState`
3. 只有确认不是 UI 事件链，再深入数据持久化、上下文广播、复杂派生计算。

### 4. 调试时要及时收敛，不要把试错补丁长期留在主线里

这次中间试过很多止血思路，例如：

- 延迟保存
- 自动保存去重
- 页面级错误边界
- 详情页整页卸载
- 时间线派生懒计算

这些在排查阶段有价值，但如果最终没有成为根因修复，就应该撤掉。  
否则后续维护者会被误导，以为问题根因在保存链或时间线，而不是交互控件本身。

## 后续建议

- 对自定义勾选、单选、开关类控件建立统一约定：
  - 尽量使用 `button` 实现视觉层
  - 避免“隐藏原生 input + 大面积 label 包裹”作为默认方案
- 在 Electron 相关 UI Bug 中，优先记录：
  - 是否有控制台错误
  - 是否会自动回到其他页面
  - 是否与 `focus/blur/mousedown` 强相关
- 对这类“无报错白屏”问题，先做最小交互替换验证，再做系统性重构。
