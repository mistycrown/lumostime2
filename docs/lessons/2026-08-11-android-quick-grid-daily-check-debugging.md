# Android 快捷栏小组件日课打卡排障复盘

日期：2026-08-11

## 问题表现

- 快捷栏的日课槽位不能正确显示当天 Daily Review 的完成状态。
- 布尔日课点击后不稳定，数值日课没有按 `0 -> 1 -> 2 -> ... -> 默认值` 的规则循环。
- 小组件内的状态和 Daily Review 的真实数据会出现偏差。
- 为了增加手动刷新，曾将刷新事件绑定到小组件根容器，随后槽位点击全部失效。

## 最终根因

### 1. 日课进度的身份缺少日期

Web 端同步给原生小组件的是一周的日课进度。同一个日课项目在不同日期会有多条记录，但原生代码最初只用 `checkItemId` 查找进度。

这会导致渲染、点击处理和缓存合并在不同场景下读到同一项目的不同日期记录。例如槽位显示的是某一天的 `0/1`，点击处理却读取了今天的 `1/1`。布尔值看起来无响应，数值值也会跳变或与 Daily Review 不一致。

修复后，所有日课进度都以 `(checkItemId, date)` 作为身份；快捷栏只读取今天的记录。

### 2. 原生动作与 Web 数据回写存在竞争

点击小组件时，原生会立即更新本地快照并把动作写入待处理队列。若旧的 Web 同步负载随后到达，它会把刚更新的原生状态覆盖掉，造成小组件显示与 Daily Review 分离。

修复方式：

- 原生合并同步负载时，保留待处理日课动作对应的本地进度。
- WebView 可用时，原生发送动作待处理事件，Web 端立即回放该动作到真实 Daily Review 数据。
- 回放完成后先把已合并的数据同步回原生，再清除待处理动作。

### 3. 同一个待处理动作被重复回放

应用恢复、页面可见性变化和原生通知可能同时触发回放。没有互斥控制时，同一条动作会被执行两次，布尔值会切回原状，数值会多加一次。

修复后，Web 端以单飞队列串行处理回放请求；正在回放时的新请求只标记为下一轮检查，不会重复执行同一动作。

### 4. 刷新事件绑定在根容器拦截了槽位点击

`RemoteViews` 的点击绑定应落在具体视图。将刷新绑定到根容器后，根点击区域覆盖了日课槽位，使原有槽位 `PendingIntent` 无法正常接收点击。

最终方案是在标题右侧使用独立刷新图标；根容器不绑定刷新。图标尺寸从 `24dp` 调整为 `20dp`，不影响槽位事件。

## 无效改动及原因

- 把刷新绑定到整个快捷栏空白区域：Android 远程视图没有可靠的“只点击空白处”命中区，根容器会与子槽位竞争点击。
- 仅检查 `PendingIntent` action、request code 或槽位布局：这些是必要检查，但日志已经证明动作能到达接收器，不能解释渲染进度与点击读取进度不一致。
- 只在场景小组件的实现中寻找点击差异：场景小组件的交互模式可作为参考，但本次故障的核心是快捷栏一周日课数据的日期选择，而不是计时器点击机制本身。
- 长期保留逐槽位和前后状态日志：这些日志帮助定位了问题，但会增加接收器噪声和维护成本，现已删除。

## 后续实现原则

1. 任何跨天日课状态都必须用项目 ID 与日期组成复合键，不能只按项目 ID 查找。
2. 小组件点击后的乐观本地更新必须有明确的队列、回放和确认顺序，避免被旧同步数据覆盖。
3. 一个用户动作只能被回放一次。应用生命周期事件需要通过串行或去重机制汇合。
4. `RemoteViews` 中的点击事件绑定到最小的实际交互视图；父容器不能承担与子项重叠的动作。
5. 调试日志应围绕“输入负载、解析记录、写入结果、回放次数”建立证据链；确认根因后删除临时日志，只保留必要的错误处理。

## 关键代码位置

- `android/app/src/main/java/com/mistycrown/lumostime/WidgetSnapshotBuilder.kt`：按当天过滤日课进度并生成快捷栏快照。
- `android/app/src/main/java/com/mistycrown/lumostime/WidgetTimerController.kt`：按项目与日期读取、修改日课状态并写入待处理动作。
- `android/app/src/main/java/com/mistycrown/lumostime/WidgetBridgePlugin.kt`：保护待处理动作对应的原生状态，并通知 WebView 回放。
- `src/hooks/useWidgetBridgeSync.ts`：串行回放原生日课动作，并在确认同步后清除队列。
- `android/app/src/main/java/com/mistycrown/lumostime/WidgetProviderSupport.java`：为标题右侧刷新图标和各槽位分别绑定点击事件。
